# 0.11.0 plan: Update-AdoToolkit

## Context

Updating AdoToolkit means downloading a release by hand and running the installer, or
extracting a new portable folder. 0.11.0 adds `Update-AdoToolkit`, the 23rd cmdlet. It finds
the newest GitHub release of `JosephGibson/Ado_tools` and verifies the download against two
GitHub checksums. It then installs beside the running copy and tells the user to open a new
window. Users on 0.10.5 or older install 0.11.0 by hand once; the cmdlet takes over from
there. `VersionPrefix` stays `0.10.5`: the release skill bumps it later, with the changelog,
the 0.11.0 release notes and the full `verify`.

**Files this plan creates** are named without their full path in code spans, so the
`documentation` stage passes before they exist. They live in these new or existing folders:
- `Update/` under `src/AdoToolkit.Core/`, and the same under `tests/AdoToolkit.Core.Tests/`.
- `UpdateAdoToolkitCommand.cs` in `src/AdoToolkit.PowerShell/Commands/`.
- `Update-AdoToolkit.md` in `docs/commands/en-US/` and `docs/commands/fr-CA/`.
- The Pester files in `tests/AdoToolkit.PowerShell.Tests/`.
- `Update.Live.ps1` in `tests/Live/`.

## Decisions

The developer decided these and the spikes confirm them:

- One command, no parameters except `-WhatIf` and `-Confirm`. No `-Version`, downgrade, `-Path`,
  pruning or `-ExpectedThumbprint`.
- The install mode is detected from the module's own base folder before any network call:
  - **Module-only**: `<root>\AdoToolkit\<version>`.
  - **Portable**: `<folder>\module` beside `Start-AdoToolkit.cmd` and `runtime\pwsh.exe`.
  - **Anything else**: refused with an error that points to the manual install steps.
- The version comes from the API's latest release, never a draft or a prerelease. Equal or
  newer: say so and stop. Older: download, verify, install, then say what was installed,
  from which version, where it went, and to open a new window. Never open a window and
  never import.
- Each zip must match both the API `digest` and the `.sha256` asset. Its size is checked
  against a cap before the download, and the downloaded length against the size afterwards.
- The updater is isolated: its own folder and its own `HttpClient`. It never uses
  `AdoHttpPipeline`, `EndpointRegistry`, credential providers, `SessionStateRegistry`,
  profiles or configuration. HTTPS only, the system proxy with default proxy credentials, no
  Windows credentials to GitHub. It follows redirects itself, only to `api.github.com`,
  `github.com` and `release-assets.githubusercontent.com`. The owner and repository are
  constants.
- The tag is parsed strictly and checked against the manifest inside the zip. Every folder
  name and URL is built from the parsed numbers.
- **Resolved during planning (developer's answer):** the gate stages the module at
  `artifacts/verify/AdoToolkit/<version>`, which has the module-only shape. So module-only
  mode also requires `<root>` to be on `PSModulePath`, compared as `Install-AdoToolkit.ps1`
  compares it. That is what lets `Import-Module AdoToolkit` find the new version.

### Flow of the cmdlet

```
[Cmdlet(VerbsData.Update, "AdoToolkit", SupportsShouldProcess = true)] [OutputType(typeof(AdoToolkitUpdate))]
RunLocal:
  using updater = new ToolkitUpdater(ModuleManifestReader.Read, TestTransport)   // disposed on any exit
  context = (Module.ModuleBase, Module.Version, PSModulePath entries, PSVersionInfo.PSVersion)
  plan = RunWorker(updater.PrepareAsync(context, log, MessageCulture, token))   // detection refuses before any request
  if plan.Result: announce + WriteObject; return      // UpToDate or AlreadyInstalled; also under -WhatIf
  if !ShouldProcess(plan.TargetPath, Messages(UpdateAction, version)): return   // -WhatIf: no object
  result = RunWorker(updater.InstallAsync(plan, log, MessageCulture, token)); write a completed progress record
  announce + WriteObject
```

- **Announce:** `WriteInformation(new HostInformationMessage { Message = Messages.Get(...) }, InformationTags)`.
  `InformationTags` is a static field holding `PSHOST`, as `ExportAdoBuildTestFailureCommand.cs`
  does, so no literal sits inside the call. The message is visible by default, captured by
  `-InformationVariable`, silenced by `6>$null`.
- **Prepare** writes nothing. In portable mode, an existing target is refused here, before any
  download. In module mode, a valid existing target becomes `AlreadyInstalled` here. So
  `-WhatIf` reads the release and its asset list, reports, and writes nothing.
- **Pipeline thread:** ShouldProcess, WriteInformation, WriteObject and progress run there.
  Progress goes through `OnProgress`, from `ReleaseDownload` events in KiB that `PipelinePump`
  throttles. The completed record's activity and status come from the catalog.

### HTTP client (`UpdateHttp`, `GitHubClient`)

**The `SocketsHttpHandler` settings:**
- `UseProxy = true`, `Proxy = null` (the system proxy, PAC included).
- `DefaultProxyCredentials = CredentialCache.DefaultCredentials`.
- `Credentials = null`, `PreAuthenticate = false`, `UseCookies = false`.
- `AllowAutoRedirect = false`, `AutomaticDecompression = None`.
- `ConnectTimeout` 30 s.

The `HttpClient` has `Timeout = InfiniteTimeSpan`. It disposes its handler only when it
created it; a test seam's handler is never disposed.

**Requests:**
- **Headers:** `User-Agent: AdoToolkit/<running version>`. API calls also send
  `Accept: application/vnd.github+json` and `X-GitHub-Api-Version: 2022-11-28`. Downloads send
  `Accept: application/octet-stream`. No `Authorization`, ever.
- **URLs**, from constants and parsed numbers:
  - `https://api.github.com/repos/JosephGibson/Ado_tools/releases/latest`
  - `https://github.com/JosephGibson/Ado_tools/releases/download/v{a}.{b}.{c}/<asset>`

  The API's `browser_download_url` and asset IDs are never used.
- **Redirects:**
  - Followed for 301, 302, 303, 307 and 308, at most 5.
  - Every hop, including the first, must be absolute `https`, on the default port, without user
    info, and on one of the three hosts (an exact match ignoring case).
  - Anything else is `AdoRedirect`, naming only the scheme and host.
  - The verbose log shows host and path, never the signed query string.
- **Limits:**

  | Limit | Value |
  | --- | --- |
  | Release JSON | 1 MiB |
  | `.sha256` | 1 KiB |
  | Module zip | 32 MiB |
  | Portable zip | 256 MiB, about 2.3 times today's |
  | Entry, uncompressed | 64 MiB, the installer's cap |
  | Module zip entries | 64 |
  | Portable entries | 5,000 |
  | Portable total, uncompressed | 1 GiB |
  | Time, API and checksum | 60 s |
  | Time, module zip | 5 min |
  | Time, portable zip | 30 min |
  | Read stall | 60 s |

  Timers run on a `TimeProvider`.
- **Body checks:**
  - A `Content-Length` other than the API size is refused.
  - The body is counted while it is read. More bytes than the API size fails at once; fewer at
    the end is a truncated download.
  - The zip is hashed as it arrives (`IncrementalHash`).
- **Retries:** none. Each message tells the user to run the command again.

### Release, checksums and archives

**Release JSON.** The root is an object, `draft` and `prerelease` are false, and `assets[]`
are objects with `name`, `size` and `digest`.
- An asset is found by its exact name, built from the version. Two matches count as malformed.
- The digest must be `sha256:` and 64 hex characters.
- `1 ≤ size ≤ cap` is checked before any download.
- The `.sha256` asset must exist, and its bytes must match its own API digest.

**Tag.** It must match `^v(0|[1-9][0-9]{0,8})\.(0|[1-9][0-9]{0,8})\.(0|[1-9][0-9]{0,8})\z`. This is
the developer's `^v\d+\.\d+\.\d+$`, made stricter:
- ASCII digits, because `\d` also matches other scripts' digits.
- `\z`, because `$` accepts a trailing newline.
- No leading zeros, and at most 9 digits per part.

Shown in a message, the tag is cut to 64 printable characters.

**Checksum file, as the installer reads it:**
- The first non-blank line, split on whitespace into at most two parts.
- The first part is 64 hex characters.
- The second part, if present, without a leading `*`, must be the zip name. The comparison is
  ordinal, where the installer's `-ne` ignores case: stricter, never weaker.

The zip's hash must equal the API digest and the checksum file's hash, ignoring case, before
the zip is opened. The file stays open with `FileShare.None` from the first byte written to
the end of extraction.

**Module zip.** The spike's rules, in the installer's order:
- Directory entries are skipped.
- `\`, `:` and a leading `/` are unsafe.
- An entry is `AdoToolkit/<a.b.c>/…`, with no `''`, `.` or `..` segment, and one version only.
- An entry is at most 64 MiB.
- The files are exactly the seven, an ordinal multiset.
- Each output path is built from the constant seven-name list, never from the entry's text.
  It must stay inside staging, is created with `CreateNew`, and must be written at the
  declared length.
- The manifest's `ModuleVersion` and `RootModule` must match.

**What the updater adds to the module checks:**
- The folder version must equal the tag's.
- At most 64 entries.
- The new manifest's `PowerShellVersion` must not exceed the running PowerShell:
  `AdoConfiguration`, nothing installed.
- Each of the three DLLs must have a valid identity, read from metadata with
  `AssemblyName.GetAssemblyName` and never loaded: its name is its file name, and its
  version is `ModuleVersion` plus `.0`, as `Assert-AdoPackage` checks
  (`tools/package/Package.Common.ps1`). This applies to staging before the commit and to an
  existing folder before it counts as installed. A truncated or relabeled DLL therefore
  fails the release, `UpdateArchiveAssembly`, or marks an existing folder incomplete.

Files written this way carry no download mark, as in the installer.

**Portable zip.** These rules follow `tools/package/Portable.Common.ps1`'s runtime checks and
`New-AdoPortableArchive`'s layout:
- **Names:** no `\ : < > " | ? *`, no control characters, no `''`, `.` or `..` segment, no
  trailing dot or space, and no reserved device name.
- **Entries:** no symlink mode, no duplicates or file/folder collisions (ignoring case), and
  empty directory entries only.
- **Top level:** exactly `Start-AdoToolkit.cmd`, `Start-AdoToolkit.ps1`, `README.txt`,
  `bundle.json`, `module/` and `runtime/`.
- **`module/`:** exactly the seven files.
- **`runtime/`:** holds the ten required runtime files listed in that script.
- **`bundle.json`** (at most 4 KiB): its `ModuleVersion` is the tag's, and `Architecture` is
  `win-x64`.
- **Manifest:** `module/AdoToolkit.psd1` matches, and the three DLLs in `module/` pass the
  identity check.
- **Caps** as listed above.
- **Free space:** checked before extraction with `DriveInfo`, against the total from the
  central directory.
- **Paths:** top-level and `module/` paths come from constants. `runtime/` paths come from
  checked entry names, which is the one remote-text-to-path exception.

### Install commit and two sessions at once

`GenerationFolderCommit` does not fit. It commits a report file plus a generation-stamped
attachment folder and prunes old generations. The updater commits one folder and must replace
a version folder exactly as the installer does. `UpdateFolderCommit` reuses its pattern
instead: a fault hook per step, and tests that compare folder snapshots.

The portable lock and staging are keyed by the destination, so two sessions that target the
same new folder from different portable folders share one lock. Nothing is written into the
running folder.

| Step | Module-only | Portable (`<dest>` = `AdoToolkit-<v>-win-x64`) |
| --- | --- | --- |
| Lock: a `lock` file in a lock folder (`FileShare.None`, `DeleteOnClose`, so a crash releases it); the empty folder is removed afterwards | `<root>\AdoToolkit\.update.lock\lock`, one per root | `<parent>\.<dest>.lock\lock`, one per destination |
| Re-check the target under the lock | A valid folder means `AlreadyInstalled` with no download; a link inside is an error | An existing folder is refused |
| Remove own leftovers, under the lock | `.update-<32hex>` beside the versions; the installer's `.staging-*` are left alone | `<parent>\.<dest>.<32hex>.tmp`, for this destination only |
| Staging (same volume, beside the target) | `<root>\AdoToolkit\.update-<32hex>\{release.zip, module\}` | `<parent>\.<dest>.<32hex>.tmp\{release.zip, bundle\}` |
| **Commit, the boundary** | If the target exists, move it to `<v>.previous-<32hex>` (failure: `UpdateInUse`). Move `module\` to `<root>\AdoToolkit\<v>`; on failure move the backup back, and if that fails too, keep the backup | Move `bundle\` to `<parent>\<dest>`; never replace |
| After the boundary | Delete the backup (a failure warns, as the installer does), and any `<v>.previous-<32hex>` whose `<v>` exists | — |
| Always | Delete staging, release the lock, remove the empty lock folder | Same |

- **The commit boundary** is the move of staging onto the target:
  - A failure up to and including that move rolls back. The previous state stays, apart from
    a backup kept when the rollback itself fails. The error is `AdoFileOutput`.
  - After that move, the new version stays installed and the result is `Installed`.
    Cleanup failures there are warnings, never errors.
- **No cancellation mid-commit:** from the first move to commit or rollback, the token is not
  checked. Ctrl+C cancels and `PipelinePump` joins the worker, so a stop cannot leave only a
  backup behind.
- **Links:** the module root and its ancestors, the portable folder and its parent, and an
  existing target must pass through no link. This mirrors `Assert-NoLink` and
  `Assert-NoLinkInside`. A link is a reparse point with a `LinkTarget`, so cloud placeholders
  are allowed.
- **A second update:** while the lock is held, a second `Update-AdoToolkit` fails at once with
  `UpdateBusy` and downloads nothing. That holds for the same root, and for the same portable
  destination even when started from different portable folders.
- **A target that appears at commit:**
  - Another updater, or the installer, can create the target after Prepare. `Directory.Move`
    never replaces, so the loser's move fails.
  - Module mode then checks the folder again: valid means `AlreadyInstalled`. Portable mode
    refuses with `UpdateTargetExists`.
- **Installer and updater at once:** this stays as racy as two installers are today, with one
  difference. The updater never deletes the installer's `.staging-*`, so it cannot break an
  install in progress.
- **Commit retries:** the commit move retries a sharing violation 5 times over about 3 s,
  because antivirus scans hold freshly written files.

### Failures: error IDs, categories and messages

These reuse the existing exception types, so `ErrorRecordFactory` and the set of error IDs are
unchanged. The error ID is the type name without `Exception`. `Operation` is set from
`UpdateHttp`'s constants, never from a literal.

| Failure | Error ID | Category | Ends the pipeline | Message key |
| --- | --- | --- | --- | --- |
| Not an installed layout, or `<root>` not on `PSModulePath` | `AdoConfiguration` | InvalidArgument | yes | `UpdateUnsupportedLayout`, naming the folder and the README's installation URL |
| The install path passes through a link | `AdoConfiguration` | InvalidArgument | yes | `UpdateLinkedPath` |
| The new manifest needs a newer PowerShell | `AdoConfiguration` | InvalidArgument | yes | `UpdatePowerShellTooOld` |
| Proxy 407, as a tunnel error or a response | `AdoAuthentication` | AuthenticationError | yes | `UpdateProxyAuthentication` |
| GitHub 403 without rate-limit headers | `AdoAuthorization` | PermissionDenied | yes | `UpdateForbidden` |
| 403 or 429 with `x-ratelimit-remaining: 0` or `Retry-After` | `AdoThrottled` | ConnectionError | no | `UpdateRateLimited` (`{0:t}`, the reset from `x-ratelimit-reset` in the provider's local time zone); `UpdateRateLimitedLater` without one |
| 404 on `latest` | `AdoNotFound` | ObjectNotFound | no | `UpdateNoRelease` |
| Asset missing from the list, or 404 on a download | `AdoNotFound` | ObjectNotFound | no | `UpdateAssetMissing` |
| 5xx | `AdoServer` | ConnectionError | no | `UpdateServer` |
| The proxy refuses the tunnel (not 407) | `AdoRequest` | InvalidOperation | no | `UpdateProxyRefused` |
| DNS, connect or TLS failure | `AdoRequest` | InvalidOperation | no | `UpdateUnreachable`, with the `HttpRequestError` name |
| The connection is lost mid-body | `AdoRequest` | InvalidOperation | no | `UpdateConnectionLost` |
| Any other status | `AdoRequest` | InvalidOperation | no | `UpdateRequest` |
| A redirect that is not allowed, plain `http`, too many hops, or no `Location` | `AdoRedirect` | InvalidOperation | no | `UpdateRedirectBlocked` |
| Total time, or a stalled read | `AdoTimeout` | OperationTimeout | no | `UpdateTimeoutSeconds`, `UpdateTimeoutMinutes`, `UpdateStalled` |
| Release JSON, tag, missing digest, oversized asset, size mismatch, digest or checksum mismatch, archive rules, manifest mismatch | `AdoResponseFormat` | InvalidResult | no | `UpdateReleaseFormat`, `UpdateTagInvalid`, `UpdateDigestMissing`, `UpdateAssetTooLarge`, `UpdateSizeMismatch`, `UpdateDigestMismatch`, `UpdateChecksumMismatch`, `UpdateChecksumFileInvalid`, `UpdateArchiveEntry`, `UpdateArchiveLayout`, `UpdateArchiveEntryTooLarge`, `UpdateArchiveIncomplete`, `UpdateArchiveAssembly`, `UpdateManifestMismatch` |
| The portable target exists | `AdoFileOutput` | WriteError | no | `UpdateTargetExists` |
| The lock is held, or the target is in use | `AdoFileOutput` | WriteError | no | `UpdateBusy`, `UpdateInUse` |
| The disk is full (HResult `0x80070070` or `0x80070027`), or the free-space check fails | `AdoFileOutput` | WriteError | no | `UpdateDiskFull` |
| A folder that cannot be read while its links or files are checked (added during implementation) | `AdoFileOutput` | WriteError | no | `UpdateFolderUnreadable` |
| Any other write failure | `AdoFileOutput` | WriteError | no | `FileOutput`, which already exists |

- **Caller cancellation** stays an `OperationCanceledException`, so Ctrl+C is a
  `PipelineStoppedException`. Staging and the lock are released in `finally`.
- **Remote text** in a message is cut to printable characters: a tag, or an entry name. Hosts
  come from the allowlist or the parsed URI, never a query string.

**Other strings (both resx files):**
- **Information:** `UpdateUpToDate`, `UpdateNewerThanRelease`, `UpdateInstalledModule`,
  `UpdateInstalledPortable`, `UpdateAlreadyInstalledModule`.
- **ShouldProcess:** `UpdateAction`.
- **Progress:** `UpdateProgressActivity`, `UpdateProgressDownload`.
- **Verbose:** `UpdateRequestLog`, `UpdateRedirectLog`, `UpdateVerifiedLog`.
- **Warning:** `UpdatePreviousInUse`.

The French entries come from `fr-translator`.

**The messages say:**
- Installed: the new version, the folder, the old version, and "close this PowerShell window
  and open a new one".
- Portable: "close this window, then start `Start-AdoToolkit.cmd` in `<new folder>`; you can
  delete `<old folder>` once its window is closed".

### Test seam

`UpdateAdoToolkitCommand` holds `internal static HttpMessageHandler? TestTransport`.
- In production it is null, and `ToolkitUpdater` creates and owns the real handler.
- Pester sets it through reflection with a handler compiled by `Add-Type`. It is not a
  parameter, an environment variable or configuration, and nothing in `src/` assigns it;
  the isolation test checks that.
- It holds a handler, not a factory, because `RunWorker` runs on a thread with no runspace.
- Core tests pass `FakeHttpMessageHandler`, a `TimeProvider` and lowered limits to an internal
  constructor.

## Live check V-38 (written, never run by an agent)

`Update.Live.ps1` takes no input variable.

1. It reads the newest installed version from its manifest, under `Get-AdoModuleRoot`, before
   any package check.
   - No install is `INCONCLUSIVE V-38 INSTALLED_MODULE_REQUIRED`.
   - An install older than 0.11.0 is `INCONCLUSIVE V-38 UPDATE_CMDLET_REQUIRED`.
2. Only then does `Assert-AdoPackage` check the install. It is not imported.
3. It copies the install to `<temp>\Modules\AdoToolkit\0.0.1` and rewrites `ModuleVersion` with
   a pure helper.
4. It runs `$PSHOME\pwsh.exe -NoProfile` as a child, with `<temp>\Modules` first on
   `PSModulePath`. The child imports 0.0.1 by path and runs
   `Update-AdoToolkit -ErrorAction Stop 6>$null`.
5. It returns only the status, or the error ID, which must match `^Ado[A-Za-z]+$`. This is a
   real download of the 0.8 MB module zip through `api.github.com`, `github.com` and
   `release-assets.githubusercontent.com`, using the work proxy.
6. It prints the verdict:
   - `Installed` with the seven files is `PASS V-38`.
   - `AdoThrottled`, `AdoNotFound`, `UpToDate` or `AlreadyInstalled` is `INCONCLUSIVE V-38 <code>`.
   - Any other error ID is `FAIL V-38 <ErrorId>`, and anything else `FAIL V-38 CHECK_FAILED`.
7. It adds `NOTE V-38 PROXY_API DIRECT|PROXIED` and `NOTE V-38 PROXY_DOWNLOAD DIRECT|PROXIED`,
   from `HttpClient.DefaultProxy`, without printing a URL.
8. Exit codes: 0, 1 or 2. The temporary folder is deleted in `finally`.

## Implementation notes

Where the code differs from the design above, or adds to it (2026-10-05):

- **More files and members:**
  - `UpdateGuards.cs` in `src/AdoToolkit.Core/Update/` holds the file-system guards: links
    (a reparse point with a target), deletion that never follows a link, the disk-full and
    sharing-violation HResults, the free-space check and printable remote text.
  - `ToolkitUpdatePlan.ArchiveName` is public. `TestTransport` is an auto-property, not a
    field.
  - `UpdateRedirectLimit` is its own message, for too many hops or a redirect without
    `Location`. `UpdateRedirectBlocked` names a hop that is not allowed.
- **Links:** for a portable copy, the check covers the parent folder and its ancestors, where
  the lock, staging and the new folder go. The running portable folder itself is never
  written, so it is not checked.
- **Lock:** the lock is a file in a folder of its own, as the table shows. A standard user
  may create folders, but not files, at the root of the system drive, where a portable folder
  may sit. A lock folder that is a link is refused with `UpdateLinkedPath`. A held lock fails
  at once with `UpdateBusy`. A lock folder that another session is removing, which Windows
  reports as missing or, while the delete is pending, as access denied, is retried with the
  commit's delays. A write failure names the path that failed: the lock file, staging or the
  target.
- **Failures the table did not list:**
  - The handler's `ConnectTimeout` ends a request as a cancellation that holds a
    `TimeoutException`. It is `AdoRequest` `UpdateUnreachable` with `ConnectTimeout`, not
    the total time limit.
  - A string in the release JSON or in `bundle.json` that cannot be read, such as a lone
    surrogate escape, is `AdoResponseFormat`.
  - A folder that cannot be read while its links or files are checked is `AdoFileOutput`
    with a new message, `UpdateFolderUnreadable`, naming the folder, as the failure table now
    shows. `FileOutput` says "Cannot write", which would be wrong for a read.
- **Messages:** `UpdateAssetTooLarge` gives both sizes in bytes. `UpdateInstalledPortable` also
  says to move any reports saved in the old folder before deleting it.
- **Zip lengths:** .NET stops reading an entry at the length that its central directory
  declares. A length that understates is never written past; one that overstates is the
  `header-length-lie` case, refused as incomplete.
- **Pester:**
  - `New-RelabeledModule` writes only a manifest that loads the staged DLLs by full path.
    Pester cannot delete `$TestDrive` while a DLL loaded from it is locked.
  - The parity table requires the `AdoResponseFormat` error ID for every refusal.
  - A test reads `$layout` in `tools/package/Install-AdoToolkit.ps1` and the required runtime
    names in `tools/package/Portable.Common.ps1` with the PowerShell parser, and compares
    them with `ModuleArchive.Layout` and `PortableArchive.RuntimeFiles`.
- **V-38:**
  - `AdoConfiguration` and `AdoFileOutput` are `INCONCLUSIVE`, like `AdoThrottled` and
    `AdoNotFound`: the work PC, not the proxy, decides them.
  - The child reports the proxy of each host: `NOTE V-38 PROXY_API`, `PROXY_SITE` and
    `PROXY_DOWNLOAD`.
  - When the temporary folder cannot be deleted, the script prints
    `NOTE V-38 TEMPORARY_FOLDER_LEFT`.
