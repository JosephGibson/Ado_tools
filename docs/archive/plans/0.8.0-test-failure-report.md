Status: decisions recorded 2026-10-03, the fourth and fifth rounds of section 7 answered the same

## 1. Outcome

| Goal | How it is judged |
| --- | --- |
| Retrieval is faster | Lower wall time, client CPU and bytes in the section 3 scenarios, with the same requests; and about 70% fewer requests with the new `-SkipAttachments` when tests rerun |
| Export is faster | Lower wall time at 0 ms and 20 ms latency for the same report |
| History reads are parallel and predictable | Earlier builds are read together; which builds fall outside the budget no longer depends on response order; the Wide scenario keeps all 10 builds at the new default budget of 500 |
| The report reads faster | The first screen says which failures are new and which recur; less chrome, one type scale, the same look |

Non-goals, decided in section 7:

- no request that relies on unconfirmed Server 2020 behaviour: no `outcomes` filter, no detail
  read from result lists, no alternative endpoints (all deferred to 0.9, section 8);
- no cache across invocations (§17 stays as written);
- no light theme (Q-30 stays: dark on screen, light in print);
- every attempt keeps its full error message and stack trace (the 0.7.0 rule stays);
- no new cmdlets, no JSON output of this report, no change to how a test is classified (§15.10).

Invariants for every phase:

- The set and the rendered report do not depend on response order or on the concurrency bound
  (`tests/AdoToolkit.Core.Tests/TestRuns/RetrievalConcurrencyTests.cs` stays green, unchanged).
- Phases 0 to 4 leave every golden in `tests/Fixtures/Reports/` byte-identical. Only phase 5
  changes goldens, through the `update-goldens` skill.
- The report stays one offline file, complete with scripts blocked, under the Content Security
  Policy of `src/AdoToolkit.Core/Reporting/TestFailures/ContentSecurityPolicy.cs`.
- The report keeps its look: the dark palette, chips, cards, status squares and view tabs. Phase
  5 tightens and fixes; it does not redesign.
- Each public-contract change is listed in the release notes.

## 2. How the report is produced today

| Stage | Code | Requests |
| --- | --- | --- |
| Build | `src/AdoToolkit.PowerShell/Commands/GetAdoBuildTestFailureCommand.cs` | 1 BuildGet with `-BuildId` |
| Runs | `TestRunService.GetRunsAsync` in `src/AdoToolkit.Core/TestRuns/TestRunService.cs` | Run pages, 100 per page, plus the empty page |
| Pass 1 | `TestRunService.GetResultsAsync` | Every result of every run, 1,000 per page, `detailsToInclude=None` |
| Pass 2 | `TestRunService.GetResultAsync` | One TestResultGet per result record of a reported test |
| Attachment metadata | `TestFailureRetrievalService.AddAttachmentsAsync` in `src/AdoToolkit.Core/TestRuns/TestFailureRetrievalService.cs` | One list per detailed record, plus one per attempt or iteration sub-result |
| Test Cases, bugs | `TestCaseLinkResolver`, `TestBugResolver` | WorkItemsBatch, 200 IDs per request, plus Bug category and states |
| History | `src/AdoToolkit.Core/TestRuns/RunHistoryService.cs` | One builds list; per earlier build, one after another: its runs, then every result page of every run |
| Export | `src/AdoToolkit.Core/TestRuns/AttachmentDownloader.cs`, `src/AdoToolkit.Core/Reporting/TestFailures/TestFailureExporter.cs` | One content request per downloaded JSON or text file |

All retrieval requests share one `RequestGate` (default 6, at most 16, from
`src/AdoToolkit.Core/Configuration/TestResultOptions.cs`). History has its own budget,
`maximumHistoryRequests`, default 500 since phase 3 (400 before).

Transport. `src/AdoToolkit.Core/Http/AdoHttpHandlerFactory.cs` builds a plain
`SocketsHttpHandler`, configured by
`src/AdoToolkit.Core/Connections/WindowsIntegratedCredentialProvider.cs`. It sets no
`AutomaticDecompression`, so nothing is ever compressed. Requests are HTTP/1.1 exact
(`src/AdoToolkit.Core/Http/RequestBuilder.cs`). That is right: IIS does not do Windows
authentication over HTTP/2, and .NET 10 does not fall back by itself. NTLM authenticates each new
connection once, with two extra round trips; `PreAuthenticate` only helps Basic.

Client-side costs found in the code:

- `src/AdoToolkit.Core/Http/ResponseJson.cs` reads every body into a byte array, decodes it to a
  string, then deserializes the string.
- Pass 1 and history pages deserialize into the full `TestResultDto` of
  `src/AdoToolkit.Core/TestRuns/TestRunDtos.cs`. Its `[JsonExtensionData]` keeps every unknown
  field of every listed result, although a listing needs eight fields (§15.9 step 3).
- The downloader flushes each attachment file to disk (`Flush(flushToDisk: true)`) before the
  generation folder is committed.

Findings:

1. Attachment metadata and pass 2 are 93% of retrieval requests whenever tests rerun. Without
   server-dependent changes, only `-SkipAttachments` removes requests at that scale (1,800 of 2,586).
2. Wall time follows latency almost linearly: retrieval is request-bound, not CPU-bound.
3. The export spends about 3 s of local work for 1,200 small files even at 0 ms latency.
4. With 8 runs of 5,000 results, nine earlier builds need about 450 history requests, so the
   default budget of 400 leaves the oldest builds unavailable. Its 451 history requests fit the
   new default of 500 (phase 3).
5. The synthetic result items are about 150 bytes. A real list item carries project, run, build
   and identity references, likely near 1 KB, so pass 1 and history move far more bytes than the
   harness shows. Phase 0 models this.
6. Harness defects: the server reported a peak of 7 requests in flight with a bound of 6 in the
   Wide scenario. A run also ended with exit code 1 because `Stop-FakeAdoServer` rethrew a write
   that the client had aborted.

Report measurements, headless Edge on the goldens:

- The header band is 157 px tall in English, 20% of a 768 px screen. It is 183 px in French and
  228 px at 1024 px wide.
- The open Details view uses 13 font sizes, from 9.98 px to 16.8 px, and has 25 text elements

7. With list items of a realistic size, the listings carry 99% of the bytes of retrieval (114.6 of
   115.8 MB, in 179 requests), while details and attachment lists carry 2,400 of the 2,586
   requests and 1% of the bytes. Phase 1 works on the first, phase 2 on the second.
8. Those bytes cost about 2 s of reading and parsing even on loopback: padding takes Get from 2.3
   to 4.3 s at 0 ms and from 14.1 to 16.1 s at 20 ms. At 80 ms the waits hide it. Wide moves
   344 MB and padded LongHistory 265 MB.
9. LongHistory's 29 earlier builds need 523 history requests (the window, then 18 per build), more
   than the new default of 500 too: it stops at the budget whatever the payload.
10. The harness defects of finding 6:
    - The peak of 7 was neither late counting nor a request escaping the gate. The excess requests
      were history listings that the client had cancelled when a sibling was refused by the
      budget, and that the server still answered. Recorded request by request, the load never
      exceeded 6 once those were left out, in Wide runs with a history budget of 60 or 120 whose
      server peak reached 11. The client never waits for more than the bound; a real server also
      finishes what the client abandons (question in section 7). The server now leaves the
      requests it sees abandoned out of its peak, and the Measure script reports them as
      `AbortedResponses`. A request abandoned while its response is being written still counts,
      so a run with cancellations can show one more than the bound (LongHistory, 158 B: 7, with 3
      abandoned). Rarely a run without cancellations shows one more too, when a server worker is
      held up between the last write of a response and the end of its count (one 0.7.10 run under
      a bandwidth cap in phase 1). The Core tests, with an in-process handler, check the bound exactly.
    - The exit code 1 came from the same requests: the write to a closed connection stopped a
      server worker. A client that leaves no longer fails the server; any other error still does.
      `tests/AdoToolkit.PowerShell.Tests/SyntheticServer.Pester.ps1` holds both regressions.
    - New: runs started one after another ran the client out of ports. The server closes every
      connection, the client's side of each one stays in TIME_WAIT for about two minutes, Windows
      has 16,384 dynamic ports, and an iteration of Default opens about 3,800 connections. The
      Measure script now waits, outside its timing, until fewer than 8,000 are held.

### Phase 3 — History reads, planned and parallel

Plan the history requests before sending any:

1. Read the window.
2. Read the runs of every window build together.
3. Compute each build's result pages from its runs' `totalTests`, with the same empty-page rule as
   today.
4. Reserve the budget newest first; a build that does not fit is marked unavailable before any of
   its pages is requested.
5. Send the reserved pages together through the gate.

A run without `totalTests` is costed the sequential way, inside its build's reservation.

This parallelizes history across builds and makes the budget outcome independent of response
order. It closes the 0.7.5 finding "Independent budgeting needs a design decision" and the
matching note on `testResults.maximumConcurrentRequests` in `docs/guides/configuration.md`.

Raise the default of `testResults.maximumHistoryRequests` from 400 to 500 (section 7). The value
appears in four places; change all of them:

- `src/AdoToolkit.Core/Configuration/TestResultOptions.cs`
- `src/AdoToolkit.Core/Configuration/ConfigurationStore.cs`
- `src/AdoToolkit.Core/TestRuns/TestFailureQuery.cs`
- `docs/guides/configuration.md`

With 500, the Wide scenario's 451 history requests fit; a wider pipeline still gets
`HistoryLimitExceeded`. A configuration default is public contract, so the release notes list
it.

## Appendix: viewing a golden with its script

Goldens replace the script with `__SCRIPT_ASSET__` and its hash with `__SCRIPT_SHA256__`. A golden
opened as-is therefore shows every view stacked, as with scripts blocked. To review one
interactively, write a copy outside the repository with both placeholders restored:

```powershell
$script = [IO.File]::ReadAllText('src/AdoToolkit.Core/Reporting/Assets/test-failures.js')
$hash = [Convert]::ToBase64String([Security.Cryptography.SHA256]::HashData([Text.Encoding]::UTF8.GetBytes($script)))
$html = [IO.File]::ReadAllText('tests/Fixtures/Reports/testfailures-grouped.en-US.html')
$html = $html.Replace('__SCRIPT_SHA256__', $hash).Replace('<script>__SCRIPT_ASSET__</script>', "<script>$script</script>")
[IO.File]::WriteAllText((Join-Path ([IO.Path]::GetTempPath()) 'testfailures-grouped.html'), $html, [Text.UTF8Encoding]::new($false))
```

Headless Edge can then capture a view, for example
`msedge --headless=new --window-size=1440,900 --virtual-time-budget=3000 --screenshot=<png> <file-uri>#details`.
