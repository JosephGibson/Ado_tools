## 1. Working rules (every session)

- Start with `pwsh -NoProfile -File .\tools\dev.ps1 context`. Read `AGENTS.md` plus the nested
  `src/AGENTS.md` and `tests/AGENTS.md`. Use `dev.ps1 find` and `rg` for focused reads; read only
  the spec sections listed for your session.
- The spec is normative; this plan gives order and scope. If they disagree, follow the spec,
  stop, and tell the user. Never change an acceptance ID.
- The gate is `pwsh -NoProfile -File .\tools\dev.ps1 verify` (exit 0 pass, 1 fail, 2 incomplete).
  Done means exit 0, `"Status":"pass"`, no warnings. Never report a result you did not observe.
- **Ask the user first** before `dotnet restore`, any package change, any install, or any other
  network access.
- No ADO access, no network in tests (fake `HttpMessageHandler`, loopback `FakeAdoServer`). Fixture
  hosts use `.test`. Tests never open files with the default handler.
- Git lifecycle belongs to the developer: inspection commands only; never create a repository,
  commit, or push.
- If the agent sandbox blocks a step this plan requires (network after the user authorizes it,
  the NuGet or PowerShell module cache outside the workspace, loopback sockets or temporary files
  during `verify`), request elevated permission for that command. Never weaken tests or the gate
  to fit the sandbox.
- Data boundary (DD-010, DD-022): synthetic fixtures only.
- Names (DD-024): no `bin`, `obj`, `artifacts`, `build`, `dist`, `coverage`, `target`,
  `TestResults`, `secret(s)` directories under `src/`, `tests/`, `docs/`; no file name matching
  `*.log`, `*credentials*`, `*.local.*`, `*.key`, `*.pem`, `*.pfx`, `*.p12`, `.env*`. Committed
  `.json`/`.xml` must parse; inputs above 1 MiB are generated by tests.
- Tag acceptance tests: xUnit `[Trait("Acceptance", "<ID>")]`, Pester `-Tag '<ID>'`.
- All labels and messages come from `.resx` in English and French. Write U+00A0 and U+202F as
  ` ` and ` ` in test code.
- Keep `tools/check.ps1` under about 240 s; report the `project-check` duration.
- End each session at a green `verify`, update `docs/plans/README.md`, and hand off: verify
  status and exit code, acceptance IDs covered, spec rows updated, authorizations used,
  deviations, open items, and new French strings for review.

**Design decisions made in this plan** (within the spec's latitude; state them in the handoff):

- The JSON document root is an object with `schemaVersion`, generator, generated-at, culture,
  collection URL, project, source, and a `cases` array; one case is an array of one. Multi-case
  export then needs no schema change.
- The report model receives generated-at and toolkit version through options, so tests pin them
  and golden files are exact bytes. No post-render normalization.
- Golden files are rewritten only when `ADOTOOLKIT_UPDATE_GOLDEN=1` is set in a manual local run.
  `tools/check.ps1` removes that variable before running tests.
- Orchestration lives in Core (`TestCaseExporter`), so `-WhatIf`, `-NoClobber`, and `-Open`
  behavior is testable without PowerShell. `IDocumentLauncher` is injected; the cmdlet passes the
  shell-execute implementation.
- Until multi-case layout exists, an invocation that receives more than one case writes a
  terminating `InvalidOperation` error before any file is created. The resource message says
  multi-case export is not available yet.

## 5. Work steps

### Session 2.1 — Model, links, writer, Downloads, JSON

1. **Baseline.** `context`, `verify`.
2. **Report model (§12.1).** `TestCaseReportModel` from an `AdoTestCase`, report culture, labels,
   connection metadata, and web links. Diagnostics are re-rendered from Code + Arguments in the
   **report** culture, never copied from `AdoDiagnostic.Message` (§7.4). Absent metadata stays
   absent. `ReportDocumentModel` wraps a list of case models (one in this slice).
3. **Links (§12.2, V-15).** Work item route exists from Slice 1; add
   `{c}/{p}/_testPlans/define?planId=…&suiteId=…`. URLs come only from the connection's collection
   URL, the project, and numeric IDs; segments are escaped and query values encoded.
4. **Atomic writer (§13.1).** Extend the Slice 0 replace primitive into a streaming writer: open the
   temp file exclusively in the destination directory, hand the renderer a UTF-8 (no BOM)
   `TextWriter`, `Flush(true)`, run the validation callback on the temp file, then move. With
   `-NoClobber`, use a non-overwriting move so a file created meanwhile is not replaced. Any
   failure deletes the temp file and leaves the destination untouched; a locked destination →
   `AdoFileOutputException` naming the path. Add injectable failure points.
5. **Downloads and file names (§13.2).** `SHGetKnownFolderPath(FOLDERID_Downloads)` through
   P/Invoke (never `%USERPROFILE%\Downloads`); `TestCase-<id>-Steps.<ext>`. `-Path` may be a file or
   an existing directory. Provider path resolution happens in the cmdlet (2.2).
6. **JSON renderer and schema (§12.4).** Stream with `Utf8JsonWriter` to the writer's stream:
   metadata, web URLs, rows (`number`, `sequence`, `kind`), parameters, Shared Steps, diagnostics
   (`code`, `arguments`, `message` in report culture), status; `-IncludeSource` adds
   `actionSource`/`expectedResultSource`. English property names and enum values in every culture.
   Write `docs/schemas/testcase.v1.schema.json` (draft 2020-12, `additionalProperties: false` where
   stable). **STOP: ask for authorization** to add `JsonSchema.Net` and restore.
7. **Validation (§12.6).** All formats: temp file exists and is non-empty. JSON: re-parse and check
   `schemaVersion`. HTML and Markdown count checks arrive in 2.2 with their renderers.
8. **Tests.** Writer fault injection (S2-3), JSON schema validation (S2-5), culture re-render of
   diagnostics, links, file names under `fr-CA` and `en-US` (machine output byte-identical).
9. `verify` → exit 0.

### Session 2.2 — HTML, Markdown, golden files, cmdlet

1. **Baseline.** `context`, `verify`.
2. **Encoder check first.** Write a small test that shows how `HtmlEncoder.Create(UnicodeRanges.All)`
   treats U+00A0, U+202F, `’`, `« »`, and an emoji. The encoders escape some characters regardless
   of allowed ranges (space separators other than U+0020, characters outside the BMP), but §11.5
   requires the no-break spaces **literally**. Implement `SinkEncoding.Html` so that U+00A0 and
   U+202F are written as literal characters: encode the segments between them, then join. Record
   how emoji end up (literal or numeric character reference) and pin it in the golden files.
   Apply the same check to the Markdown path.
3. **HTML renderer (§12.2).** `<meta charset="utf-8">` first; CSP meta exactly
   `default-src 'none'; style-src 'unsafe-inline'; img-src data:`; `<html lang>` = report culture;
   generator meta `AdoToolkit <version>`; `data-case-count` on the document; `data-step-count` per
   case. Use embedded CSS from `testcase-report.css` (§12.2 layout, 700 px breakpoint, print
   styles; dark screen palette per the owner's Q-21 revision, light print output). Include the header fields in the specified order
   with absent fields omitted, the title linked, the parameters table after the header with
   shared-set links, step cards with outline numbers, and Shared Steps banners opening indented
   groups (unexpanded groups styled as warnings with their localized message). The diagnostics
   section comes last. No `<script>` anywhere.
4. **Content links (§12.2, DD-008).** Absolute `http`, `https`, and `mailto` URLs in step text
   become `<a rel="noreferrer">`; every other scheme stays text. Link text and `href` are encoded
   separately; `href` is attribute-encoded.
5. **Markdown renderer (§12.3).** One heading per step prefixed with its number; Shared Steps
   groups as blockquote banners with links; `[text](url)` with parentheses percent-encoded;
   escaping per §11.4; `’ « »` untouched; labels in report culture.
6. **Validation (§12.6).** HTML: generator marker, `data-case-count`, each `data-step-count`, and
   the rendered step card count equals the model row count. Markdown: case and step heading counts.
   Scan the temp file as a stream; do not load the document into memory.
7. **Golden files (S2-1).** Cases: direct, nested, partial, parameterized, French content. Report
   cultures: `en-US` and `fr-CA`. Formats: HTML, Markdown, JSON. That makes 30 files in
   `tests/Fixtures/Reports/`, named `testcase-<case>.<culture>.<ext>`, LF line endings, pinned
   generated-at and version. Review the first English and French HTML output by opening it
   locally in a browser before approving it.
8. **`Export-AdoTestCase` cmdlet.** Pipeline input `AdoTestCase`; collect in `ProcessRecord`, render
   in `EndProcessing`. Parameters: `-Format Html|Markdown|Json` (default Html), `-Culture`
   (resolution order §3.6; unsupported → English + warning), `-Path` (FileSystem provider
   required, parent must exist, file or directory), `-NoClobber`, `-IncludeSource` (JSON only; with
   another format, a terminating `InvalidArgument` error before any work), `-Open`. `SupportsShouldProcess`: `-WhatIf` lists the
   target and writes nothing. Output: `FileInfo`. Check `CollectionUri` provenance. Add help in
   both cultures.
9. **Pester `Export.Pester.ps1`.** Get cases from `FakeAdoServer` fixtures, then test `-WhatIf`,
   `-NoClobber`, `FileInfo` output, `-Path` directory handling, `-Culture fr-CA`, and the
   unsupported culture warning. Never pass `-Open`.
10. **Core exporter tests.** `-Open` calls the injected launcher once with the committed path,
    and never on failure or `-WhatIf`.
11. Run the offline done check (section 7).

## 10. Risks

| Risk | Mitigation |
| --- | --- |
| HTML encoder escapes U+00A0/U+202F (and emoji) despite `UnicodeRanges.All`, conflicting with §11.5 | Encoder check is the first step of 2.2; literal no-break spaces by segment encoding; pinned by S2-7 |
| Golden churn from CSS or label edits | Pinned clock and version; one approval pass with a browser review; update only via the explicit environment variable |
| Validation needs counts without loading large documents | Streaming scan of the temp file for markers |
| P/Invoke analyzer rules (`LibraryImport`, `AllowUnsafeBlocks`) under warnings-as-errors | Keep the interop in one `KnownFolders` class; configure only Core as needed |
| Downloads folder synced by OneDrive locks temp files | Temp file in the destination directory; locked destination gives a clear `AdoFileOutputException` |
| `JsonSchema.Net` unavailable on the work feed | Test-only; the work publish script restores and publishes only the product projects |
| Accidental script or remote resource in HTML | S2-2 scans for `<script`; CSP forbids everything else |
| Hostile text in attributes (`title`, `href`) | Attribute encoding tested with quotes and angle brackets |
