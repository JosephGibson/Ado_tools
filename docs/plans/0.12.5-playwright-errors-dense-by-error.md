# 0.12.5 plan: Playwright errors in the classifier, and a denser By error

Playwright's messages recognized, its action timeout set apart as a generic error, and each
error group and each test of By error on one line.

## Context

- **Playwright is not in the catalog.** `ErrorTemplates.Match`
  (`src/AdoToolkit.Core/Reporting/Errors/ErrorTemplates.cs:38-43`) knows MSTest, xUnit, NUnit
  and Selenium's wait timeout. A Playwright message falls through to the tokenized key line
  (`ErrorForms.Text`, `src/AdoToolkit.Core/Reporting/Errors/ErrorForms.cs:85-89`).
- **Its first line does not name what failed.** The element is in the call log below it, so
  the key line alone joins unrelated failures:
  - every action timeout of a build, `System.TimeoutException : Timeout 30000ms exceeded.`,
    is one error, whatever element it waited for;
  - every `Locator expected to be visible` is one error, whatever locator;
  - every `Page URL expected to be '…'` is one error: the URL is a slot (`ErrorText.Variable`).
- **The action timeout is environmental at work** (developer, 2026-10-08): it is the error
  seen most, and it comes from the environment. As a specific error it is the most frequent
  error of many tests, so it becomes their primary error and hides their assertion failures,
  which is what 0.12.0 set out to stop.
- **By error is not dense.** Each group takes three or four lines: the exception type, the
  line (`.cluster-head` is a two-row grid, `src/AdoToolkit.Core/Reporting/Assets/test-failures.css:125-127`),
  the facts row and the **Sample message** summary. A test's **Errors** cell stacks its
  placement, its other errors and the previous build on separate lines
  (`.other-errors, .previous-error { display: block; }`, `test-failures.css:146`), and a test
  with many errors wraps its list of other errors over several lines.

**Research, 2026-10-08, on branch `0.12.5` at 09ae930.** Nothing was changed.
- **Code read:** the classifier, the catalog, the rules, the clusters, the By error renderer
  and its stylesheet, the fixtures and goldens of the failed-test report.
- **Text sources:** `Microsoft.Playwright` 1.63.0, the latest release, and 1.41.2, from

- **Line numbers** are those of that commit. Find each place by its content before editing.

## Decisions (developer, 2026-10-08)

1. **Playwright's action timeout is generic.** A built-in rule sets it apart, as the rules of
   0.12.0 set apart a lost WebDriver session.
2. **No built-in deadlock rule.** Its texts can be read only from vendor documentation, not
   from a package; the configuration guide shows a configured rule for it instead.
3. **By error:** each group heading, each facts row and each test row on one line, cut at
   the width of the table, the rest readable on hover.

## Findings that shape the design

- **F-1 The timeout.** Both versions throw `System.TimeoutException`; neither defines a
  Playwright timeout type. `Connection.ParseException` builds it from the driver's message and
  the call log: `new TimeoutException(error.Message + FormatCallLog(log))`. The driver writes
  `Timeout {n}ms exceeded.`, and `Timeout {n}ms exceeded while waiting for event "{e}"` for an
  event wait. The test frameworks print it as `System.TimeoutException : Timeout 30000ms
  exceeded.` (NUnit, xUnit) or `System.TimeoutException: …` (MSTest), which
  `ErrorText.Prefix` already reads.
- **F-2 The call log.**
  - 1.63.0: `"\nCall log:\n" + string.Join("\n", log)`, each entry `  - text`, a repeated run
    `  9 × text` with its other lines indented (`compressCallLog`).
  - 1.41.2: `"\nCall log:\n  - " + string.Join("\n  - ", log)`.
  - The first entry of an action or an assertion on a locator is `waiting for {locator}`, with
    ` to be {state}` for a wait for a selector; a navigation logs
    `navigating to "{url}", waiting until "{state}"`. Retries add lines such as
    `attempting click action` and `element is not visible`, whose number varies.
  - Trimmed, the entries read `- waiting for …` or `9 × waiting for …`.
- **F-3 The assertion.** `AssertionsBase.ExpectImplAsync` throws `PlaywrightException`:
  - `{custom}\n\n` first when the test passed its own message;
  - then the message, such as `Locator expected to be visible`,
    `Locator expected to have text`, `Locator expected to have attribute '{name}'`,
    `Page URL expected to be`, `Page title expected to be`; `expected not to` for a negated one;
  - 1.63.0 only: `\n{ErrorMessage}`, such as `Error: element(s) not found`. The client adds
    the `Error: ` (`Frame.ExpectAsync`, `Frame.cs` at `v1.63.0`) to the driver's
    `customErrorMessage`, from which the driver strips its own `Error: `; so the line always
    starts `Error: `;
  - then ` '{expected}'\nBut was: '{actual}' ` when there is an expected value, else ` `. With
    an error message, the expected value therefore ends the error line, not the head;
  - then the call log, whose first entry is the assertion with its timeout,
    `Expect "ToBeVisibleAsync" with timeout 5000ms` (1.63.0) or
    `LocatorAssertions.ToBeVisibleAsync with timeout 5000ms` (1.41.2), then
    `waiting for {locator}`; a page assertion has no locator line.
  - Every assertion message of both versions, 36 string literals in 1.63.0 and 26 in 1.41.2,
    starts `Locator expected`, `Page expected`, `Page title expected` or `Page URL expected`;
    some are completed at run time, such as `Locator expected ` + `to be attached`.
- **F-4 A closed browser.** `TargetClosedException` with the driver's default text "Target
  page, context or browser has been closed", the same in both versions, and "Target crashed "
  followed by the browser's log (1.63.0). Nothing shows that it comes from the environment
  rather than from a test that closed its page, so it stays out of the built-in rules
  (Critique 2).
- **F-5 Reach.** A message is read on its first 20 lines (`ErrorMessageStart.MaximumLines`),
  and a template reads at most 10 lines after its head (`ErrorTemplates.MaximumFollowingLines`).
  An assertion's locator line is the fifth after its head at most (error line, `But was`,
  `Call log:`, the assertion's entry, then the locator) when the values hold no line break, so
  both reach it; a multi-line value can push it out, and the form is then keyed without it.
- **F-6 Rules and parts.** A rule's matches are one form, and that form keeps the layout and
  the parts that the reading found (`ErrorForms.cs:43-54`). So a timeout template whose element
  is a slot lets the rule's one group show each test's element in the **Values** column and
  underline it in the group's line. But `ErrorClusters.Of` finds the slots that vary in the
  first member's parts only (`src/AdoToolkit.Core/Reporting/TestFailures/ErrorClusters.cs:112`):
  a first member without a call log would hide the others' elements (Critique 3).
- **F-7 Limits.**
  - Any edit of `test-failures.css` rewrites the 14 failed-test goldens.
  - The script must stay under 16 KiB (`ScriptAssetTokenScanTests`); this plan does not touch it.
  - The 200 × 14 report must stay under its byte budget
    (`tests/AdoToolkit.Core.Tests/Reporting/TestFailures/ErrorTextTests.cs`).

## Design

### D-1 `Playwright.Timeout` template

- **Head,** on the line where the form starts, folded:
  `^(?:{type} ?: )?timeout (?<n>[0-9]+)ms exceeded(?:\.| while waiting for event "(?<x>.*)")$`.
- **Target:** within reach after the head, the `call log:` line, then the first entry that
  reads `waiting for {t}` or `navigating to {t}`, after a leading `- ` or `{count} × `.
- **Identity:** the event and the target. Without either the form is located: the test's own
  frame tells its errors apart, as for the other templates without identifying text.
- **Parts:** the head as sent, the milliseconds a slot; then ` · ` and the target entry
  without its marker, the target a slot of its own (a new `TargetSlot`).
- **Language:** neutral; Playwright writes English only.

### D-2 `Playwright.Expect` template

- **Head:** `^(?:{type} ?: )?(?<k>(?:locator|page|page title|page url) expected .*?)(?: '(?<e>.*)')?$`,
  on the start line, or on a later line within reach when the start line opens with
  `Microsoft.Playwright.PlaywrightException`: the lines before the head are then the test's
  own message, however many (F-3, Critique 4).
- **Following lines,** within reach: `error: {d}`, ending with ` '{e}'` when the head has no
  expected value (F-3, Critique 1); `but was: '{a}'`; and the call log's first
  `waiting for {t}`; the assertion's own entry is skipped.
- **Identity:** the kind (`k`), the expected value from the head or the error line, the test's
  own message and the target. For `page url expected to be`, the expected URL is keyed by its
  path, without scheme, host, query or fragment: the host changes between environments, the path
  says which page. A segment is a slot only when the whole segment is a number, a GUID or a
  hexadecimal ID as `ErrorText` reads them, so `/orders/1234` and `/orders/1235` are one page
  and `/oauth2/callback` and `/saml2/callback` are two (Critique 5).
- **Slots:** the expected value, the actual value (`But was`), the error line, the target.
- **Parts:** the head, then the target, then `But was`, then the error line: what identifies
  the error comes first, so a cut line keeps it.
- **Order in `Match`:** after `Xunit`, before `NUnit`.

### D-3 Built-in rules

- **`PlaywrightTimeout`** (Decision 1), generic: a line that is `Timeout *ms exceeded.`, tried
  as every rule is, so also after its leading `System.TimeoutException : `. Name: **Playwright
  timeout**. The event wait (`… while waiting for event …`) is left out: waiting for a
  download or a popup that never comes says something about the test.
- After the five rules of 0.12.0. A configured rule still comes first, so `"generic": false`
  with the same pattern keeps the timeout among the specific errors.
- **No other rule.** A closed browser (F-4) and a database deadlock (Decision 2) are shown as
  configured rules in the configuration guide.
- **Values across the group (Critique 3).** `ErrorClusters.Of` finds the varying slots in the
  parts of every member, not the first one only; a member without a slot that others have
  counts as a different value, and its Values cell shows the values it has.

### D-4 A denser By error

- **Group heading, one line:** the count, the rule or the exception type, then the line, which
  takes the rest of the width and ends with `…` where it is cut; its title holds the whole
  line. The two-row grid of `.cluster-head` becomes one flex row. Less padding above the
  heading.
- **Facts, one row:** the facts as today, then the **Sample message** summary at the end of the
  same row; opened, the sample takes the full width under it. The row wraps only when its facts
  do not fit.
- **Test rows, one line:** the **Errors** cell writes the placement, the other errors and the
  previous build on one line, separated by ` · `, cut with `…`; its title holds the whole
  text, other errors with their counts. Links that are cut stay reachable by keyboard.
- **Print:** cells wrap again, since a printed page has no hover.
- **Open bugs** shares the table classes; its rows are checked unchanged.

### D-5 Tests and fixture

- `ErrorFormsTests`: each template in both versions' forms; the timeout's forms with
  different call-log noise, compressed and uncompressed, are one form; different targets are
  two; without a call log the form is located; the assertion's actual value only varies; two
  expected values stay apart when an error line carries them; a negated assertion; the test's
  own message on one line and on two; page URLs under two hosts, with a number segment and with
  `oauth2` against `saml2`; the rule, and a configured `generic: false` rule that wins over it.
- `ErrorClassifierTests`: a test whose attempts are mostly timeouts and once an assertion gets
  the assertion as primary error; the timeouts of several tests make one generic group whose
  members' targets differ.
- `ErrorClustersTests`: a group whose first member has no target and whose others have one
  shows every target, in both member orders.
- `ByErrorViewTests`: the heading's parts in one row, the sample inside the facts row, the
  Errors cell as one line with its title.
- **Fixture:** a `playwright` variant of `TestFailureReportFixture` with invented locators on
  `.test` hosts: timeouts on several elements across tests, one without a call log, assertions on
  locators and on a page URL, a test with timeouts only. Goldens `testfailures-playwright.*.html`.

### Deviations

1. **D-2 head.** The kind stops at the first quote, except for the quoted name of `to have
   attribute '…'`, `to have CSS property '…'` and `to have JavaScript property '…'`, and the
   closing quote of the expected value may be missing. The plan's pattern put an attribute's name
   into the expected value; a value of several lines would not have matched at all.
2. **D-2 head on a later line.** The head is the last line before the call log that reads as
   one, not the first: a test's own message that starts like `Page expected …` stays the test's.
3. **D-2 parts.** An expected value read from the error line shows right after the head, with
   its quotes as sent, and the error line shows without it: what identifies comes first, as D-2
   asks, in both versions' forms alike.
4. **D-2 located.** An assertion with no expected value, no message of the test's own and no
   locator is located, as D-1 makes the timeout and as the catalog makes a condition. The plan
   did not say.
5. **Targets.** A call-log entry `waiting for "{url}" navigation to finish...`, which 1.63.0
   logs before acting and first for a page assertion, names no element and is skipped. The
   timeout's target key keeps its verb, so a wait and a navigation never share a key.
6. **Errors cell title.** It holds the other errors' labels uncut; the cell shows them cut at
   60 characters, as before.
7. **Screenshots at 1600 pixels.** Every heading, facts row and test row of `bilingual`, `large`
   and `playwright` is one line, but one: group 1 of `bilingual`, whose facts hold every kind of
   fact. Measured in Edge, their text alone is about 1,490 pixels against 1,446 available, so no
   spacing fits it without shorter labels; D-4 lets a facts row wrap when its facts do not fit,
   and that row wrapped before this pass too. At 1000 pixels the table is wider than the window,
   as before (1,068 and 1,273 pixels against 970); this pass does not change that.
8. **Fixture.** The test without a call log is named `AddCoupon`, so that it sorts first in the
   timeout group and the golden shows the case of Critique 3. The variant uses the 1.63.0 forms.
9. **Deadlock example.** `docs/guides/configuration.md` shows `*chosen as the deadlock victim*`,
   from SQL Server's message 1205 as its documentation words it, not from a package (Decision 2).

## For the release notes

**What changed for a user.**
- Playwright's errors are recognized: its assertions group by what they assert, the kind (such as
  `Locator expected to have text`), the expected value, the test's own message and the locator
  read from the call log. The actual value only varies, and an expected page URL counts by its
  path, so one page under two hosts is one error.
- Playwright's action timeout, `Timeout 30000ms exceeded.`, is a generic error: By error lists it
  under **Generic errors** as **Playwright timeout**, with each test's element or page in
  **Values**, and a test whose attempts mostly timed out and once failed an assertion is listed
  under the assertion. A wait for an event stays specific.
- By error is denser: each group heading and each test row is one line, cut at the width of the
  table with the whole text on hover; the facts and the **Sample message** share one row, which
  wraps only when the facts do not fit; the **Errors** cell joins its parts with middle dots. In
  print the group's line and the Errors cell wrap.

**Public contract.** The CSV column `Error rule` can hold the new built-in rule ID
`PlaywrightTimeout`. Reports of builds with Playwright tests group differently: their timeouts
leave the specific errors. A configured rule with the pattern `Timeout *ms exceeded.` and
`"generic": false` keeps them specific.

**Goldens.** The 14 failed-test goldens were regenerated through `update-goldens` for the
stylesheet and the By error markup: the line's title, the sample inside the facts row, the
Errors cell's title and middle dots. Each equals its previous version once those changes are
undone. `testfailures-playwright.en-US.html` and `testfailures-playwright.fr-CA.html` are new;
