# 0.8.5 plan: a styling pass on the failed-test report

Status: released as 0.8.5 on 2026-10-03, after the developer approved the last design pass.
`docs/release-0.8.5.md` records the tests, goldens, documents and validation. Branch `0.8.5`.

This plan is for the agent sessions that implement 0.8.5. `AGENTS.md` and the nested `AGENTS.md`
files still govern. Scope: the HTML report that `Export-AdoBuildTestFailure` writes. The Test
Case report, `report-base.css` and the script stay as they are.

## 1. Outcome

| Goal | How it is judged |
| --- | --- |
| The report is easier to get into | Overview says at a glance what is new, what recurs, which errors dominate and what has no bug |
| Density sits between 0.7.10 and 0.8.0 | Overview, Runs and history, By error and Open bugs get more room; Details keeps 0.8.0 |
| Columns line up | Every part of a test row has its own column, in both cultures |
| Colour carries meaning | Red for failures and bugs, green for passes, amber for flaky, violet for new; always with a glyph or text |
| Details reads faster | Dated run history, the class in the title, attachments on the card, aligned labels and attempt summaries, a quieter current card |
| By error and Open bugs do analysis | Clusters merge numbers, GUIDs, paths and hex IDs; each says its exception type, spread, new or recurring, groups and bug coverage; each bug says what it covers and what it misses |

Non-goals: no new request or endpoint (Server 2020 behaviour is unconfirmed; section 9 keeps the
ideas), no light theme, no new script behaviour, no change to how a test is classified.

## 2. Invariants

Deliberate rules, kept and still tested:

- No `content:` in CSS, so no generated glyph or marker; no `scroll-margin-top` (the focus offset
  is `html { scroll-padding-top }`); no `url(`, `@import` or `prefers-color-scheme`.
- Five type sizes, `--text-11` to `--text-16`; 11 px only for the brand (and the external-link
  glyph rule, now unused here: section 8).
- `.attempt > summary` and `.attempt[open] > summary` are the only two such rules and set no
  `display`, so the native disclosure marker stays.
- `<details class="attempt">` keeps exactly that class; no `<details>` starts open; `<article>`
  is a card and nothing else; ids are unique (`TestFailureReportValidator`).
- No nested `<section>` inside Overview, By error or Open bugs.
- `is-current`, `aria-current` and `is-match` never use `--flaky`; the first line of
  `src/AdoToolkit.Core/Reporting/Assets/test-failures.css` keeps its tokens; every `var(--x)`
  without a fallback is declared in the two stylesheets.
- `src/AdoToolkit.Core/Reporting/Assets/test-failures.js` is unchanged (13,349 of 16,383 bytes).
- `HtmlTestFailureRenderer.LatestError` keeps its name, signature and first-line behaviour: the
  console table shows the same line.
- History data counts stay plain cells (S5-5).
- The report-size budgets of `CompactReportTests` and `ErrorTextTests` hold.
- Works with scripts blocked (every view, in the new order), in print and under the Content
  Security Policy; keyboard, filters, chips and the sticky band behave as in 0.8.0; the band
  fits the French labels.

## 3. Baseline

Headless Edge 154 on the 0.8.0 goldens with the script restored, every view at 1440 and
1920 px in both cultures, and the 0.7.10 goldens the same way (`artifacts/preview/baseline/`,
outside the repository's history).

- Rows: 26 px in 0.8.0 (13 px, line height 1.45, 3 × 8 px padding), 28 px in 0.7.10 (13.1 px,
  line height 1.6). The dense feel of 0.8.0 is mostly the Test cell, which runs name, signal,
  Open bug marker and class name inline, the 8 px gutters and the tight spacing between blocks.
- Columns that move from row to row: the Test cell in Overview, By error and Open bugs; History
  by test (name and class); the Runs table (name, ID, Latest run); the bug list of a card (IDs of
  different widths); attempt summaries (the title's width and an optional server outcome shift
  every part after them).
- The card's history strip uses about 250 of 1,350 px. The current card has a 2 px blue outline,
  and `j` or `k` adds a second 2 px focus ring.
- The fixtures have one or two tests, one error cluster and at most two bugs, and the grouped one
  has no history: too small to judge the Overview cards, By error or Open bugs. The previews add
  a synthetic `large` set (section 7).

## 4. Design

### 4.1 Views in a new order

Overview, Runs and history, Details, By error, Open bugs, then Diagnostics when present. The
sections in the page follow, so print and a page with scripts blocked read the same. Overview
stays the default view. The script finds views by id, so it needs no change.

### 4.2 One column per part

Every table of tests: `# | Test Case | Test | Class | Trend | Open bugs | groups or Attempts | last`.
The last column is Latest error in Overview, Values in By error (only when a cluster has values
that differ), and Linked through in Open bugs. Open bugs shows in Overview and By error only.

- `#` holds the status glyph and the ordinal close together. The ordinal is right-aligned in a span
  as wide as the largest ordinal: two digits, three from 100 tests (a `:has()` rule on the
  Overview's rows), so 1, 10 and 100 still end at the same place.
- Test holds the name link alone, still cut at 26rem with the whole name as its title. Class and
  Values are cut through an inner span, since a cell ignores `max-width`. Class, Values and Latest
  error are in `--text-soft` (#d2d6dc, 11.7:1 on the surface), brighter than muted text.
- Trend holds the trend chip (4.4), centred in its column in every table, or nothing when there
  is no comparison.
- Open bugs holds the lowest-numbered open bug as a red chip, `#801`, with `+N` when there are more
  (their numbers as its title); a bug that could not be read shows the same chip in grey, titled
  "Not read"; otherwise the cell is empty.
- Latest error holds the first line of the error on one line, cut by the cell as in 0.8.0, with the
  whole line as the cell's title; it takes the width the other columns leave. Every row of the
  Overview is one line.
- History by test: `# | Test | Class | builds | Trend`.
- Runs: the run name, then its ID in a column of its own; "Latest run" sits at the end of the run
  cell, so it lines up; a grouped build has one row group per pipeline group, with a heading.
- Heading rows of By error and Open bugs lay out their parts on a fixed grid inside the cell, so
  they line up from one group to the next. A card's bug list is a grid: ID, title, state.
- Attempt summaries keep the native `<summary>`. The title, status, duration and machine have
  fixed minimum widths (title 7rem, 8.5rem in French), the machine is cut at 12rem, a missing
  duration or machine keeps its place, and the server outcome (`Timeout`) moves after the machine.
  Group summaries line up the same way.
- `colspan` comes from the table's column list.

### 4.3 Density

`:where(#overview, #runs, #by-error, #bugs)` gives table cells 4 × 12 px and line height 1.4:
rows of 28 px, every one a single line. Headings get 16 px
below, a level-3 heading 24 px above. Heading rows of clusters and bugs get 16 px above their
text, so a jump lands clear of the sticky column header. The History data table gets the same
cells. Details keeps the 0.8.0 values.

### 4.4 Colour as information

| Meaning | Colour | Glyph and text |
| --- | --- | --- |
| Failed, flaky, passed, other | `--fail` #ff6b6b, `--flaky` #ffc53d, `--pass` #3ddc84, `--other` (shared) | ✕ ≈ ✓ – and the word |
| New in this build: it passed in the previous one | The only filled chip: `--new` #b38cff background, dark text | ✦ New |
| Recurring: it also failed or was flaky in the previous build | Orange, `--recurring` #ff953e: a pill with orange text on an orange tint, wherever it shows (chips, the Recurring counts, the card's bar) | Since 9/13/2026, linked |
| An open bug | A red chip, `--fail`, wherever it shows: the Open bugs column, bug headings, a card's bugs, Associated bugs, the With an open bug fact | `#801` |
| A bug that could not be read | The same chip, in grey, wherever it shows: it may be closed | `#802` and "Not read" |
| Links | `--link` #5eb5ff | Underline on hover |

- These colours are brighter than the shared ones and live in this report's stylesheet only.
  Contrast on the four surfaces (#111315, #131619, #191c20, #23272d): fail 5.4 to 6.7:1, pass 8.4
  to 10.4:1, flaky 9.5 to 11.8:1, link 6.8 to 8.4:1, new 5.8 to 7.2:1; the background on violet
  7.2:1; the orange text of a Since chip on its tint 5.1 to 5.7:1 on the surfaces chips sit on.
  `ThemeContrastTests` passes.
- Orange sits between the failure red and the flaky amber, so it cannot clear the validator's
  floor for colours told apart by hue alone: #ff953e is the most distinct choice that keeps amber,
  ΔE 11.4 from red for normal vision and 7.9 for deuteranopia. It is a status colour with its own
  text and shape: the chip says "Since", and it is a pill where a bug is a square chip.
- Red now means both a failure and a bug, as the developer asked; the glyph, the `#` and the
  column say which. The `dataviz` validator found the status colours rely on their glyphs for
  colour-blind readers (failed and passed are close for deuteranopia), as in 0.8.0.
- Print: #a32222, #176329, #725000, #004d99, #5b2f9e and orange #8a4100 on white (7.3 to 9.0:1); chips print as
  outlines. Forced colours: borders in CanvasText; the text carries the meaning.

### 4.5 Overview

The table first, then one row of compact cards, each left out when it would be empty:

1. New and recurring: how many tests are ✦ New, Recurring or have No comparison, one count per
   line with the chips of one width, and one thin bar of the three shares.
2. Most common errors: the three largest clusters of two tests or more, with their exception type
   and line; each opens the cluster in By error.
3. Without an open bug: "n of m tests", then the three that most need a bug, longest failing
   first, then new ones, each with its trend chip; a link opens the Without an open bug group of
   Open bugs. Shown only when some test has an open bug.
4. By group, in a grouped build: per group, failed, flaky and failing only there.

No legend: the glyphs and chips carry their words, and every status cell has a title such as
"2 of 2 failed". The cards describe the whole build; the filters act on the table.

### 4.6 Runs and history

- The run history chart comes first, centred in its panel, with its History data table.
- The Runs table splits as in 4.2. Passed and Failed read `✓ 38` and `✕ 2` in status colour, muted
  at zero; the latest run's row has an accent on its leading edge.
- History data: "This run" is a pill; the counts stay plain cells.
- History by test: each cell is a small box tinted by its status, with its glyph, a dashed box for
  a build that did not run the test, and a muted one for an unavailable build. Class has its own
  column; the last column is the trend chip.
- No ↗ after links or chart captions.

### 4.7 Details

- The card has no coloured top edge. Its title shows the class, muted, before the test's name:
  `OrdersApiTests.CancelOrder`; the full name stays below with Copy.
- The current card shows a 1 px ring at 55 % of `--current` (3.9:1). A card focused from the
  keyboard shows a 2 px ring at 70 % of `--focus` (5.6:1, enough for WCAG 2.4.13). Both are offset
  2 px; forced colours use Highlight.
- Order inside a card: header, full name with Copy, facts (Run history, Bugs, Attachments), the
  metadata, then the attempts. Facts and metadata share one label width: 7.5rem, 10rem in French.
- Run history, as in 0.7.10: one chip per build with its status glyph and the day it finished, in
  the report's culture and offset (`9/14/2026`, `2026-09-14`); the build number is in its title and
  accessible name. Shapes still tell the states apart (filled, hatched, dashed, dotted); the
  current build is the last chip, its date in bold, without the shared stylesheet's ring. The trend
  chip follows on the same line. The dates join the card's search text, as the dates of its attempts
  already do.
- Bugs: each bug as the same chip as in the Overview (red, or grey when it could not be read),
  then its title and state. An attempt's Associated bugs show the same chips.
- Attachments: each file name once, from the last attempt that has it: the file, linked to its
  original, its size, then the attempt it comes from, which opens that attempt at the file with
  its local copy and preview, and `×2` titled "Attempts: 1, 3" when several attempts have a file
  of that name. One entry per name keeps the report within its size budget (14 attempts of 100
  tests would otherwise repeat every file).
- Inside an attempt, each attachment is a row: name and size on the left, the local copy on the
  right, its details and preview below across the row.
- Metadata of the card, of an attempt and of a group: pairs on a grid,
  `repeat(auto-fill, minmax(min(100%, 19rem), 1fr))`, label then value. Comment and the JSON of
  custom fields take a whole row.
- Attempts: aligned summaries (4.2). Inside an attempt that failed, the error message has a
  `--fail` edge and text in `--text`; the stack trace tints the first frame of the test's own code
  as well as edging it, dims framework frames further and opens up its line height. The Copy,
  Wrap and Framework buttons are quiet buttons that show their border on hover and focus; a
  pressed one is in link colour; each stays 24 px high.
- Sub-results and iterations put their heading, status and outcome on one line.

### 4.8 By error

`src/AdoToolkit.Core/Reporting/TestFailures/ErrorClusters.cs` clusters the tests once per report;
the Overview and Open bugs use the same clusters.

- The key line is the whole first line of the latest error, not the 240-character cut. When it
  ends with a colon and the next line is an exception header, as in MSTest's "Test method X threw
  exception:", the next line is the key line.
- URLs, GUIDs, Windows, UNC and Unix paths, hexadecimal IDs (word-bounded, at least eight hex
  digits mixing digits and letters, or `0x…`) and numbers become placeholders of their kind; tests
  whose key lines then match share a cluster. `HtmlTestFailureRenderer.ErrorKey` returns the same key.
- An attempt's summary in Details shows the key line too, cut at 240 characters, so an MSTest
  attempt shows its exception rather than "Test method X threw exception:". The Overview's Latest
  error column keeps the first line, which the console table shares (section 10).
- A cluster shows the line of its first test without its `Type:` prefix. A value that differs
  between the tests is underlined and titled "Differs between tests: a, b, c, d, e (+n)". The line
  is cut at 240 visible characters, never inside a marked value.
- The exception type is the first `…Exception` or `…Error` followed by a colon at the start of a
  line of the message, then of the trace, preferring the innermost one after `--->`; the cluster
  shows its most common type by its short name, with the full name as title.
- The common frame is the most common first frame in the test's own namespace, shown when at least
  two tests share it.

Layout: one table with the shared columns and a sticky header. Each cluster is a row group with
its id (`e-1`, `e-2`, …) and a heading row: count, exception type, line. A cluster of two tests or
more also has a facts row and a sample:

- facts: ✕ failed and ≈ flaky counts; ✦ New and Recurring counts; With an open bug, in red with
  the bug chips, and Without an open bug; a count per pipeline group; the common frame;
- a closed "Sample message" with the first test's message, at most 1,000 characters and 12 lines,
  copyable and wrappable like a card's; long lines never widen the table, even with scripts
  blocked.

Above the table: "Distinct errors: n · Tests: m". No legend. Largest cluster first, ties by first
test; tests without a message last. A test row shows the values that differ in the Values column.

### 4.9 Open bugs

- A bug's heading is one line, wrapping only when it must: count, the bug's chip, its title in
  bold, its state, "Not read", its work item type when it is not Bug, its project when it is not the
  build's, then what it covers: Linked tests, Same Test Case, not linked, and Same error, not linked
  (a link to the largest such cluster in By error), and, in a grouped build, how many of its tests
  fail in each group. No legend.
- Linked through says how far a link through test results reaches: "Test result: 2 of 3 failed
  results". Reruns share their parent result's bugs, so the count is by result. It is left out
  when the bug is also linked through the Test Case.
- Tests that share a Test Case with a linked test but not the bug follow its linked tests, muted,
  as "Same Test Case, not linked". This happens only for a bug that reaches its tests through test
  results: a bug linked to a Test Case is on every test of it.
- Tests with the same error are counted, not listed: a generic error would flood the view.
- A last group, Without an open bug (`no-bug`), lists every test that no open bug tracks. It shows
  when some test has an open bug and some other test does not.

### 4.10 Diagnostics

Last, unchanged.

## 7. Previews

`artifacts/preview/render-previews.ps1`, outside the repository's history, renders the previews
from the Release build of the Core tests:

```powershell
dotnet build AdoToolkit.slnx --configuration Release --no-restore
pwsh -NoProfile -File .\artifacts\preview\render-previews.ps1 -Screens
```

- `grouped`, `flaky` and `partial` come from `TestFailureReportFixture` through reflection; each
  report is checked by `TestFailureReportValidator`.
- `large` is synthetic, built from the public types: two pipeline groups of two runs, ten builds
  of history, sixteen tests with long names, clusters of several tests (numbers, paths and GUIDs
  that differ, exception types, an MSTest first line, a shared helper frame), streaks from one to
  eight builds, flaky tests, a bug that covers only some failed results, a bug linked through
  results only with a test of the same Test Case left out, a bug that could not be read, and
  attachments on several attempts, some downloaded, one too large. Hosts end in `.test`; the names
  are invented.
- Every report is written in en-US and fr-CA only, as
  `artifacts/preview/testfailures-<variant>.<culture>.html`, with the real script, and again with
  the script removed (`.noscript.html`).
- `-Screens` captures every view at 1440 and 1920 px into `artifacts/preview/screens/` through the
  DevTools protocol of a headless Edge on a local port, and prints the band's height and the first
  table row's height at 1280, 1440 and 1920 px. A plain `msedge --screenshot` leaves content
  scrolled past about two window heights unpainted, so it would show far cards as an empty page.
  It also writes a tall screenshot of each report with its script removed, and a printed PDF of the
  grouped report's Details.
