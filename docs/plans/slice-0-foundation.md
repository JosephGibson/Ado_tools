## 1. Working rules (every session)

- Start with `pwsh -NoProfile -File .\tools\dev.ps1 context`. Read `AGENTS.md` and any nested
  `AGENTS.md` that covers the paths you change. Use `dev.ps1 find` and `rg` for focused reads; do
  not read the whole tree or the whole spec. Read the spec sections listed for your session.
- The spec is normative; this plan gives order and scope. If they disagree, follow the spec,
  stop, and tell the user. Never change an acceptance ID.
- The gate is `pwsh -NoProfile -File .\tools\dev.ps1 verify`. Exit 0 = pass, 1 = fail,
  2 = incomplete. A session is done only at exit 0 with `"Status":"pass"` and no warnings. Never
  report a result you did not observe.
- **Ask the user first** before `dotnet restore`, adding or upgrading any package, installing a
  PowerShell module or tool, or any other network access. `verify` never restores or installs.
- No ADO access and no network in tests. Core tests use a fake `HttpMessageHandler`; Pester
  tests use a loopback-only fake server on `127.0.0.1`. Fixture hosts use `.test`.
- Git lifecycle belongs to the developer: inspection commands only; never create a repository,
  commit, or push.
- If the agent sandbox blocks a step this plan requires (network after the user authorizes it,
  the NuGet or PowerShell module cache outside the workspace, loopback sockets or temporary files
  during `verify`), request elevated permission for that command. Never weaken tests or the gate
  to fit the sandbox.
- Data boundary (DD-010, DD-022): fixtures are hand-written and synthetic. Never ask for or paste
  real work data.
- Names (DD-024): no directory named `bin`, `obj`, `artifacts`, `build`, `dist`, `coverage`,
  `target`, `TestResults`, `secret`, or `secrets` under `src/`, `tests/`, or `docs/`; no file name
  matching `*.log`, `*credentials*`, `*.local.*`, `*.key`, `*.pem`, `*.pfx`, `*.p12`, or `.env*`.
  Malformed or DTD-bearing fixtures end in `.txt`. Inputs above 1 MiB are generated by tests.
- Tag every acceptance test with its ID: xUnit `[Trait("Acceptance", "S0-3")]`, Pester
  `-Tag 'S0-3'`.
- All user-facing text comes from `.resx` resources in English and French.
- `tools/check.ps1` must finish well inside the template's 300-second stage timeout (target
  under 240 s on this PC). Report the `project-check` duration from the verify JSON.
- End each session at a green `verify`, update the status table in `docs/plans/README.md`, and
  hand off with: verify status and exit code, acceptance IDs now covered, spec rows updated,
  authorizations used, deviations, and open items.

### Session 0.3 — HTTP pipeline

1. **Handler (§5.1).** `WindowsIntegratedCredentialProvider` configures `SocketsHttpHandler`:
   `Credentials = CredentialCache.DefaultCredentials`, `UseProxy = true`, `Proxy = null`,
   `DefaultProxyCredentials = DefaultCredentials`, `AllowAutoRedirect = false`,
   `UseCookies = false`, `PooledConnectionLifetime = 15 min`, normal certificate validation.
   Test the constructed handler's properties; no network.
2. **Registry (§6.2).** `EndpointDefinition` exactly as specified. Register only `ProjectsList` in
   this slice. The `IdChunks` paging value may exist in the enum but is not implemented yet.
   Registry tests: unique names, exact versions (no bare `-preview`), safe-retry flags.
3. **Request construction (§6.3).** Segment escaping with `Uri.EscapeDataString`, an encoder for
   the query string, `api-version` injected only here, `Version = HttpVersion.Version11`,
   `VersionPolicy = RequestVersionExact`, `Accept-Language` on each `HttpRequestMessage` from the
   captured UI culture (never on client defaults), invariant formatting.
4. **JSON.** Source-generated `AdoJsonContext`; internal DTOs; mapping to `AdoProject` and
   `AdoIdentityRef`; no `JsonElement` leaves Core.
5. **Paging (§6.4).** ContinuationHeader and TopSkip with the caller's `-Top` limit separate from
   page size. Guards: repeated token, repeated offset page, more than 10,000 pages →
   `AdoResponseFormatException`. A short or empty page with a token continues; TopSkip advances by
   the count returned and stops on an empty page.
6. **Retry (§6.5).** Safe-to-retry only; 429, 502, 503, 504, and transient connection errors; no
   retry on 500, authentication, certificate, invalid response, or cancellation. At most 3
   attempts; `Retry-After` in seconds or as an HTTP date, capped at 60 s; otherwise 1 s then 2 s
   ±20% jitter. Injected clock, delay, and jitter. New request per attempt; responses disposed.
   Verbose log per retry.
7. **Timeouts (§6.6).** Infinite `HttpClient.Timeout`; linked token per timeout class; Metadata
   and Query use the profile timeout (default 100 s); Download uses 10 min total and 60 s of
   inactivity (mechanism and tests now, streaming consumers later). `AdoTimeoutException` is
   distinct from caller cancellation, and caller cancellation wins.
8. **Error translation (§6.7).** Status table; optional `message`, `typeKey`, `ActivityId`;
   invalid error body never hides 401/403 or changes retry; IIS 401 HTML never parsed or echoed;
   remote text bounded and sanitized. A 400 api-version rejection adds the registry-mismatch hint.
   A French server error body passes through with the toolkit's French hint (Localization
   fixture 3).
9. **Request logging (§6.8).** Verbose: `GET ProjectsList 200 143 ms attempt=1`; Debug: route,
   operation, page counts. No headers, bodies, query values, or continuation tokens.
10. **Test infrastructure.** `tests/AdoToolkit.Core.Tests/Http/FakeHttpMessageHandler.cs`:
    scripted responses from `tests/Fixtures/Rest/`, recorded requests (method, URI, headers,
    body, attempt), and controllable delays and blocking for timeout and cancellation tests.
11. **Fixtures.** HTTP fixtures 1–13 and 16–18 from §19.3. Fixture 16 (malformed JSON) is
    `malformed-body.json.txt`; fixture 17 is an empty body. Catalog each in
    `tests/Fixtures/README.md` (what, source, V-item).
12. **Cancellation core.** A request blocked in the fake handler observes the invocation token,
    throws `OperationCanceledException` (not a timeout), and is not retried.
13. Extend `CultureInvarianceTests` with request URIs (TopSkip `$top`/`$skip`), `Retry-After`
    date parsing, and timeout values.
14. `verify` → exit 0.

### Session 0.4 — Cmdlets, session state, help, packaging, live check

1. **Session state (§3.4).** `SessionStateRegistry`: runspace-keyed weak registry resolved on the
   pipeline thread. Each holder owns `HttpClient` instances per connection key and session caches
   (§17: projects, 15-minute TTL, bounded LRU). `Connect-Ado`, `Disconnect-Ado`, and runspace
   disposal release only that holder, after in-flight work ends.
2. **`AdoCmdletBase` (§3.3).** Synchronous callbacks; worker tasks send typed events into a bounded
   queue; the active callback drains the queue and calls `Write*` while waiting. `StopProcessing`
   cancels and wakes the pump without writing or waiting. `finally` disposes resources;
   `PipelineStoppedException` is preserved. Workers never touch `SessionState`, providers, or
   `ShouldProcess`. Capture `$PSUICulture` at invocation entry. Map exceptions to `ErrorRecord`
   (§8.2) with `FullyQualifiedErrorId = <Code>,<CmdletClass>`; the code is the exception name
   without `Exception`. Put cmdlet classes in namespace `AdoToolkit` so IDs read
   `AdoAuthentication,AdoToolkit.TestAdoConnectionCommand`. Terminating versus non-terminating
   follows §8.3. Add `-Connection` resolution and the §4.4 `ConnectionMismatch` helper.
3. **Cmdlets (§16 S0 rows).** `Connect-Ado` (`-CollectionUrl`, `-Profile`, `-Project`; resolution
   order §4.3), `Disconnect-Ado`, `Get-AdoConnection` (emits nothing when disconnected),
   `Test-AdoConnection` (projects call; success, elapsed, requested API version, hint; a failed
   projects call may suggest a project URL, never asserts it), `Get-AdoProfile`,
   `Set-AdoProfile` and `Remove-AdoProfile` (ShouldProcess, atomic config writes; parameter names
   mirror the config keys), `Get-AdoProject` (`-Name` wildcard per §11.5). Argument completers:
   `-Profile` from local config, `-Project` from the session cache only. Every cmdlet declares
   `[OutputType]`. Format views for `AdoConnection`, `AdoProfile`, `AdoProject`,
   `AdoConnectionTestResult`.
4. **Manifest.** `PowerShellVersion = '7.6'`, `CompatiblePSEditions = @('Core')`, explicit
   `CmdletsToExport`, `FormatsToProcess`, no scripts to process, no preference changes.
   `ModuleVersion` is stamped from the MSBuild `Version` at publish
   (`dotnet msbuild -getProperty:Version`).
5. **Fake server for Pester.** `Support/FakeAdoServer.ps1`: a `System.Net.Sockets.TcpListener` on
   `127.0.0.1` with an ephemeral port, running in a thread job, serving scripted fixture responses
   and recording requests. It can also accept a request and never answer (cancellation). No
   `HttpListener`, so no URL ACL or elevation is needed.
6. **Pester surface tests** (`*.Pester.ps1`, one topic per file): parameter sets and pipeline
   binding; `-WhatIf` and atomic writes on profile cmdlets with a temporary
   `ADOTOOLKIT_CONFIG_PATH`; import leaves preferences unchanged; French authentication failure;
   cancellation. For §16.1's hard-coded string rule, add
   `tests/AdoToolkit.Core.Tests/Localization/HardCodedStringTests.cs`: a source scan of
   `src/**/*.cs` that fails on string literals passed to `WriteWarning`, `WriteVerbose`,
   `WriteDebug`, `ProgressRecord`, `WriteInformation`, `ErrorDetails`, or `Ado*Exception` message
   arguments, with an explicit, commented exemption list for machine text.
7. **Help (Q-11, Q-14).**
   - **STOP: ask for authorization** to install `Microsoft.PowerShell.PlatyPS` 1.x
     (`Install-PSResource` or `Install-Module`, CurrentUser scope) from PSGallery.
   - Write Markdown help for each S0 cmdlet in `docs/commands/en-US/` and `docs/commands/fr-CA/`:
     synopsis, description, every parameter, at least one example.
   - The publish script generates MAML into the package. For compiled cmdlets `Get-Help` looks for

## 10. Risks

| Risk | Mitigation |
| --- | --- |
| Pester ordering assumption wrong (V-09) | Spike in session 0.1 before building on it; fallback §20 option 1 |
| `project-check` exceeds the template's 300 s timeout as tests grow, especially with the double culture run | Release build once, `--no-build` test runs, one publish; track duration each session |
| Locked DLLs after importing the module | Pester and help spikes run only in child processes |
| `System.Management.Automation`'s dependency packages add runtime DLLs to the package despite `ExcludeAssets="runtime"` (§3.2) | Package inspection in `check.ps1` fails the gate; fix asset flags in the project file |
| An agent sandbox blocks restore, module installs, the NuGet cache, or loopback sockets | Request elevated permission for that command after authorization; never adapt tests to the sandbox |
| Work SDK band lower than home | `global.json` `10.0.100` + `latestFeature`; lock files with `--locked-mode` at work |
| Work feeds lack a package or PSGallery is blocked (V-12) | Few test-only packages; if PlatyPS is unavailable at work, hand-maintained MAML (Q-11 override) |
| Group Policy enforces signing, so `-ExecutionPolicy Bypass` in hooks and `project-check` has no effect at work | `verify` stays a home activity; only package, sign, install, and live scripts run at work, signed locally |
| Pipeline pump deadlocks or writes from worker threads | Bounded queue, tests with timeouts, cancellation tests in Core and Pester |
| Loopback fake server blocked by firewall or proxy settings | Bind `127.0.0.1` only; .NET bypasses the proxy for loopback; fail with a clear message |
| Satellite and help culture lookup differs from expectations (V-17) | Spike; ship both regional folders if unsure |
| Documents folder redirected at work | Install script resolves the Documents known folder |
| DD-024 name collisions (for example a file named `...Credentials...`) | Rule in `src/AGENTS.md` and `tests/AGENTS.md`; agents are denied reading such files |
