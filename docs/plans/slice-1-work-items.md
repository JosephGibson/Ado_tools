## 1. Working rules (every session)

- Start with `pwsh -NoProfile -File .\tools\dev.ps1 context`. Read `AGENTS.md` plus the nested
  `src/AGENTS.md` and `tests/AGENTS.md`. Use `dev.ps1 find` and `rg` for focused reads; read only
  the spec sections listed for your session.
- The spec is normative; this plan gives order and scope. If they disagree, follow the spec,
  stop, and tell the user. Never change an acceptance ID.
- The gate is `pwsh -NoProfile -File .\tools\dev.ps1 verify` (exit 0 pass, 1 fail, 2 incomplete).
  Done means exit 0, `"Status":"pass"`, no warnings. Never report a result you did not observe.
- **Ask the user first** before `dotnet restore`, any package change, any install, or any other
  network access.
- No ADO access, no network in tests: Core uses the fake `HttpMessageHandler`; Pester uses the
  loopback `FakeAdoServer`. Fixture hosts use `.test`.
- Git lifecycle belongs to the developer: inspection commands only; never create a repository,
  commit, or push.
- If the agent sandbox blocks a step this plan requires (network after the user authorizes it,
  the NuGet or PowerShell module cache outside the workspace, loopback sockets or temporary files
  during `verify`), request elevated permission for that command. Never weaken tests or the gate
  to fit the sandbox.
- Data boundary (DD-010, DD-022): synthetic fixtures only; never request or paste work data.
- Names (DD-024): no `bin`, `obj`, `artifacts`, `build`, `dist`, `coverage`, `target`,
  `TestResults`, `secret(s)` directories under `src/`, `tests/`, `docs/`; no file name matching
  `*.log`, `*credentials*`, `*.local.*`, `*.key`, `*.pem`, `*.pfx`, `*.p12`, `.env*`. Malformed or
  DTD-bearing fixtures end in `.txt`; inputs above 1 MiB are generated by tests.
- Tag acceptance tests: xUnit `[Trait("Acceptance", "<ID>")]`, Pester `-Tag '<ID>'`.
- All user-facing text, including diagnostic messages, comes from `.resx` in English and French.
  In test sources write no-break spaces as ` ` and ` `, never as literal invisible
  characters.
- Keep `tools/check.ps1` under about 240 s (the template kills it at 300 s); report the
  `project-check` duration.
- End each session at a green `verify`, update `docs/plans/README.md`, and hand off: verify
  status and exit code, acceptance IDs covered, spec rows updated, authorizations used,
  deviations, open items, and new French strings for review.

## 5. Work steps

### Increment 1A — Work items

1. **Baseline.** `context`, `verify` (exit 0).
2. **IdChunks(n) (§6.4).** Split ID lists into chunks of at most n, request sequentially,
   reassemble in input order. Test 450 IDs → 3 requests (HTTP fixture 14).
3. **Registry.** `WorkItemsBatch`: POST `{c}/_apis/wit/workitemsbatch`, `6.0`, IdChunks(200),
   safe to retry, Query timeout class.
4. **Request body (§9.1).** `ids`, `errorPolicy: "omit"`, and `fields` = `-Field` ∪ the fields
   behind the §7.3 convenience properties. `Id` and `Rev` come from the top level. With
   `-IncludeRelations`: `"$expand": "relations"` and no `fields`.
5. **Reconciliation (§9.1, V-05).** Never zip request and response positions. Accept both null
   placeholders and compacted omissions (HTTP fixture 15, both variants). Missing IDs = requested
   − returned. An unexpected or duplicate returned ID → `AdoResponseFormatException`.
6. **Field mapping (§6.3, §7.4).** Convenience properties typed; `Fields` is a case-insensitive
   read-only dictionary keyed by reference name. Unknown arrays and objects become read-only lists
   and dictionaries. Identity-shaped objects become `AdoIdentityRef`. Never infer dates or
   identities from string contents. `WebUrl` = `{c}/{p}/_workitems/edit/{id}`, where `{p}` is the
   item's own `System.TeamProject`, escaped as a segment (V-15). Always request
   `System.TeamProject` for that reason.
7. **`Get-AdoWorkItem` cmdlet.** `-Id <int[]>` with `ValidateRange(1, int.MaxValue)`, pipeline by
   value and by property name `Id`; `-Field <string[]>`; `-IncludeRelations` in its own parameter
   set, so `-Field` with `-IncludeRelations` is rejected locally (V-10; do not describe it as a
   server rule); `-Connection`. Buffer in `ProcessRecord` and retrieve in `EndProcessing`.
   Validate typed pipeline input provenance before reducing to IDs (§4.4): a mismatch writes
   `ConnectionMismatch` with no request. Dedupe on first occurrence; emit in input order; one
   non-terminating `ObjectNotFound` error per missing ID.
8. **Format view and help** (`docs/commands/en-US/`, `docs/commands/fr-CA/`), resources.
9. **Pester `WorkItems.Pester.ps1`.** Binding by value and property name, error records per
   missing ID, parameter-set rejection, and mismatch without any request (fake server request log
   empty).
10. **Live script skeleton.** Create `tests/Live/TestCase.Live.ps1` with V-05 and V-10 checks
    (section 8). Increment 1C completes it.
11. `verify` → exit 0.

### Increment 1B — Pure parsers and diagnostics

1. **Baseline.** `context`, `verify`.
2. **Diagnostic model.** `AdoDiagnostic` per §7.3 (Code, Severity, invariant Arguments, Message,
   WorkItemId, StepNumber, ReferenceChain). A renderer produces Message from Code + Arguments +
   explicit `CultureInfo`. Add English and French resources for all 16 Slice 1 codes in §8.5
   (`NotAStepContainer` through `UnresolvedSharedParameter`).
3. **Safe XML (§10.3 rule 1).** One settings factory: `DtdProcessing.Prohibit`, `XmlResolver = null`,
   comments and processing instructions ignored, `ValidationType.None`,
   `MaxCharactersInDocument = 10,485,760`, reader over the string only.
4. **Rich-text converter (§11.2–§11.3, §11.5).** Hand-written tokenizer (no regular expressions for
   markup). Apply the tag table, then steps 1–6. Repeat whole conversions until stable, at most 8
   passes; `NestedEncodingDecoded` when more than one pass changed the text. No Unicode
   normalization. French no-break spaces kept next to `: ; ! ? « »` and between digits; other
   no-break spaces become spaces; both characters written literally.
5. **Steps parser (§10.3 rules 2–8).** Root must be `steps`; element children of the root only, in
   document order; local-name matching. For `step`: first two `parameterizedString` values, a
   warning for extras, type mapping or inference, and `isformatted` routing to the converter.
   Retain `ActionSource`/`ExpectedResultSource` as XML-decoded inner values. For `compref`: `ref`
   only; invalid → reference node marked invalid + `InvalidSharedStepReference`; child elements →
   `UnexpectedComprefChildren`, skipped, reference kept (V-01). Other elements →
   `UnknownStepElement`. Malformed → `MalformedStepsXml` with line and position, no nodes. Output
   is a pure `StepDocument`.
6. **Parameter parsers (§10.6, V-03).** `Microsoft.VSTS.TCM.Parameters` declared names in order.
   Local `LocalDataSource`: DataSet-style XML, skip `xs:schema`, rows as name/value pairs, element
   names decoded with `XmlConvert.DecodeName` (accented names). Shared `LocalDataSource`: JSON
   mapping of test parameter names to shared parameter set IDs. Shared parameter set XML parser
   (joined in 1C). Failures → `MalformedParameterData` (Warning). Never `DataSet.ReadXml`. Mark
   each assumed shape "[V-03]" in the fixture catalog.
7. **Fixtures.** Steps 1–9, 17–19, 23 (malformed root and malformed Shared Step, as `.xml.txt`),
   26, 27 (DTD attempt, `.xml.txt`), 29; Parameters 1, 3, 4 (malformed variants as `.txt`), 6, plus
   a parse-level shared mapping for Parameters 2. Save as UTF-8. Fixture 9 includes NFD accents,
   U+00A0, U+202F, `’`, `« »`, and emoji.
8. **Optional V-01 oracle spike** (only if authorized; outside the repository): parse the same
   synthetic steps XML with the helper and compare structure. Record "offline oracle agrees /
   differs" in the V-01 cell; live confirmation is still required.
9. **Tests.** Converter tests (S1-5); parser and parameter tests at document level (part of S1-2).
10. `verify` → exit 0.

### Increment 1C — Detection, expansion, `Get-AdoTestCase -Id`

1. **Baseline.** `context`, `verify`.
2. **Capability detection (§10.4).** Registry `WorkItemTypeCategory`: GET
   `{c}/{p}/_apis/wit/workitemtypecategories/{category}`, `6.0`. Rules 1–3 in order. Category
   membership is cached per project in the session cache. A failed lookup is neither cached as
   empty nor reported as `NotAStepContainer`; it surfaces as the translated HTTP error.
3. **Phase 1 resolver (§10.5.1).** Invocation-scoped cache object (no static state). Seed the cache
   with the root documents, so a root that another root references is not fetched again.
   Frontier = `compref` IDs of all roots; level loop up to `MaximumSharedStepDepth`; fetch only
   IDs not in the cache with the listed fields and `errorPolicy = omit`, in chunks of 200; omitted
   IDs → Unresolved. Referenced shared parameter sets are fetched in the same way, in the first
   batch round. Their data is assumed to be in `Microsoft.VSTS.TCM.Parameters` on the shared
   parameter work item; mark that assumption [V-03]. Budget
   `testCases.maximumResolvedWorkItems` (default 10,000): when exhausted, stop fetching; affected
   references stay unexpanded with `ResolutionLimitExceeded`.
4. **Phase 2 expander (§10.5.2, §10.5.4).** Implement the pseudo-code exactly: outline `Number`
   strings, `Sequence`, `SharedStepPath` without the root, `Depth`, group rows with
   `IsExpanded`. Unexpanded group rows keep their number and carry `DiagnosticCode`. Cycles are
   checked against the active path, which starts with the root (self-reference). Depth limit →
   `MaximumDepthExceeded`. A resolved reference whose item has no steps data (fixture 21) → group
   row with no children and `SharedStepHasNoSteps` (Warning). When the row count passes
   `MaximumExpandedSteps`, emit exactly one
   `Truncated` row with `ExpansionLimitExceeded` and stop all expansion. `SharedSteps` lists
   distinct references with `ReferenceCount` = group occurrences in the bounded output.
   `StepCount` counts Action and Validate rows.
5. **`TestCaseService`.** Root batch with the §10.1 fields; detection per root; parse; Phase 1 across
   all roots of the invocation; Phase 2 per root; parameter join (local rows, or shared rows via
   the mapping, `UnresolvedSharedParameter` for missing sets); metadata null when absent;
   `Status = Partial` when any Error diagnostic exists; `RetrievedAt`, `CollectionUri`, `WebUrl`.
6. **`Get-AdoTestCase` cmdlet (ById).** `-Id <int[]>` pipeline by value and property `Id`;
   `-MaximumSharedStepDepth` and `-MaximumExpandedSteps` override config; `-Strict`; `-Connection`.
   No `-Project` in this parameter set: IDs are collection-wide, and category lookups use each
   item's `System.TeamProject`. Buffer and retrieve in `EndProcessing`. Missing root → `ObjectNotFound`; not a step
   container → per-input `NotAStepContainer` error. A `Partial` case emits the object plus one
   warning with the ID and diagnostic counts; with `-Strict` it emits a non-terminating error
   carrying the diagnostics instead (§8.4). Format views for `AdoTestCase` and `AdoTestStep`.
   Help in both cultures.
7. **Fixtures.** Steps 10–16, 20–22, 24, 28; Steps 25 (fan-out) generated in the test; Parameters
   2 and 5; category responses; multi-level batch response sequences. Update the catalog.
8. **Tests.** S1-2 end to end, S1-3, S1-4, S1-6, plus Pester `TestCases.Pester.ps1` for `-Strict`,
   the partial warning, `NotAStepContainer` error records, and binding.
9. **Finish `tests/Live/TestCase.Live.ps1`** (section 8).
10. Run the offline done check (section 7).

## 8. Live checks at work (later)

Runs from the signed, installed module (setup in the roadmap's work track). The script reads
`ADOTOOLKIT_LIVE_PROFILE` plus test case IDs from `ADOTOOLKIT_LIVE_TESTCASE_ID` (a case with
nested Shared Steps) and `ADOTOOLKIT_LIVE_SHARED_PARAM_CASE_ID` (optional). IDs live only in the
environment. The script may call REST directly with `Invoke-RestMethod -UseDefaultCredentials`
for raw-shape checks. It prints only `PASS|FAIL|INCONCLUSIVE <V-ID> <structural note>` and writes
nothing.

| Item | Check |
| --- | --- |
| V-01 | Every `compref` has a positive integer `ref`; report whether any `compref` has child elements |
| V-02 | `isformatted="true"` strings contain escaped markup; unformatted strings contain no markup |
| V-03 | `Parameters` and `LocalDataSource` parse without `MalformedParameterData` for a local and (if given) a shared parameter case; accented names decode (inconclusive if no such case) |
| V-05 | A batch with the given ID plus `2147483647`: report "null entry", "omitted", or "error" |
| V-10 | A raw batch with both `fields` and `$expand=relations`: report accepted or the status code |
| V-13 | Category endpoint returns `Microsoft.TestCaseCategory` and `Microsoft.SharedStepCategory` with at least one type each |

**S1-7** passes when every item is PASS, or when the developer has described each mismatch
structurally (§19.2), the fixtures were corrected at home, `verify` passed, and the rerun passes.
Manual acceptance run (DD-022): run `Get-AdoTestCase -Id <case>` and compare numbering and
group rows against the ADO web UI by eye; record pass/fail only.

## 10. Risks

| Risk | Mitigation |
| --- | --- |
| Parameter formats (V-03) are based on secondary sources and may be wrong | Isolate parsing behind `ParameterDataParser`; mark fixtures [V-03]; recommend the early work checkpoint W1 after this slice |
| `compref` children semantics (V-01) | Skip with a warning, never double-count; optional offline oracle |
| Null placeholders versus omission (V-05) | Reconcile by ID; test both shapes |
| Category reference names (V-13) | Detection rule 1 (steps field present) covers most cases; lookup failure never becomes `NotAStepContainer` |
| Nested-encoding loop over-decodes literal text | Pinned trade-off fixture 8; `-IncludeSource` keeps originals |
| Invisible no-break spaces corrupted by editors | ` `/` ` escapes in test code; fixture files checked byte-wise |
| Off-by-one in the Phase 1 request bound | S1-6 counts requests exactly; seed roots into the cache |
| Exponential fan-out memory or time | `MaximumExpandedSteps` checked after each emitted row; generated fixture |
| DTD and malformed fixtures break the configuration stage | `.txt` extension (DD-024) |
