## 1. Working rules (every session)

- Start with `pwsh -NoProfile -File .\tools\dev.ps1 context`. Read `AGENTS.md` plus the nested
  `src/AGENTS.md` and `tests/AGENTS.md`. Use `dev.ps1 find` and `rg` for focused reads; read only
  the spec sections listed for your session.
- The spec is normative; this plan gives order and scope. If they disagree, follow the spec,
  stop, and tell the user. Never change an acceptance ID.
- The gate is `pwsh -NoProfile -File .\tools\dev.ps1 verify` (exit 0 pass, 1 fail, 2 incomplete).
  Done means exit 0, `"Status":"pass"`, no warnings. Never report a result you did not observe.
- **Ask the user first** before `dotnet restore`, any package change, any install, or any other
  network access.
- No ADO access, no network in tests (fake `HttpMessageHandler`, loopback `FakeAdoServer`). Fixture
  hosts use `.test`.
- Git lifecycle belongs to the developer: inspection commands only; never create a repository,
  commit, or push.
- If the agent sandbox blocks a step this plan requires (network after the user authorizes it,
  the NuGet or PowerShell module cache outside the workspace, loopback sockets or temporary files
  during `verify`), request elevated permission for that command. Never weaken tests or the gate
  to fit the sandbox.
- Data boundary (DD-010, DD-022): synthetic fixtures only. Real logs are work data and never enter
  the repository.
- Names (DD-024): no `bin`, `obj`, `artifacts`, `build`, `dist`, `coverage`, `target`,
  `TestResults`, `secret(s)` directories under `src/`, `tests/`, `docs/` (the Core folder is
  `Builds/`, which is allowed); no file name matching `*.log`, `*credentials*`, `*.local.*`,
  `*.key`, `*.pem`, `*.pfx`, `*.p12`, `.env*`. Log fixtures are `.txt`. Inputs above 1 MiB are
  generated by tests.
- Tag acceptance tests: xUnit `[Trait("Acceptance", "<ID>")]`, Pester `-Tag '<ID>'`.
- All messages come from `.resx` in English and French.
- Keep `tools/check.ps1` under about 240 s; report the `project-check` duration.
- End each session at a green `verify`, update `docs/plans/README.md`, and hand off: verify
  status and exit code, acceptance IDs covered, spec rows updated, authorizations used,
  deviations, open items, and new French strings for review.

## 5. Work steps

### Session 4.1 — Definitions, builds, timeline, failure derivation

1. **Baseline.** `context`, `verify`.
2. **Registry.** BuildDefinitionsList, BuildsList (ContinuationHeader), BuildTimeline, and
   BuildLogsList (`Accept: application/json`) exactly as in §6.2. Mark continuation-header
   fixtures [V-14].
3. **`Get-AdoBuildDefinition`.** `-Project`, `-Name` wildcard (§11.5 matching), `-Id`. Emit
   `AdoBuildDefinition`.
4. **`BuildQuery` (§15.2).**
   - `-Definition <string|int>`: an integer → `definitions=<id>`; a string → resolve through
     BuildDefinitionsList by exact name. Zero or several matches → error stating the count and
     suggesting `-Definition <id>`.
   - `-Branch main` → `branchName=refs/heads/main` unless it already starts with `refs/`.
   - `-Latest` → `$top=1` and `queryOrder=finishTimeDescending`; with `-Latest`, `-Status`
     defaults to `Completed`, otherwise to `All`.
   - `-Status Completed|InProgress|All` → `statusFilter`; `-Result` (closed enum of build results)
     → `resultFilter`; `-Top` limits results, separate from page size.
5. **`Get-AdoBuild`.** Pipeline `AdoBuildDefinition` by value; `-Connection`, `-Project`. Emit
   `AdoBuild` with the build web link.
6. **Timeline (§15.3 step 1).** `Get-AdoBuildTimeline -BuildId`, pipeline `AdoBuild` by value.
   Emit records in tree order (parent then children by `order`).
7. **Failure derivation (§15.3 steps 2–5).** Build the tree from `parentId`. For each `identifier`,
   keep only the highest attempt; drop superseded records with their subtrees. A failure is the
   deepest record with `result = failed`, or `canceled` when the build was canceled (a record with
   no qualifying descendant). `Path` joins ancestor names with ` › `. `-IncludeWarnings` adds the
   deepest `succeededWithIssues` records. Line counts come from one BuildLogsList call per build.
   Emit in tree order.
8. **`Get-AdoBuildFailure`.** `-BuildId`, pipeline `AdoBuild` by value; provenance check (§4.4).
9. **Fixtures.** Timelines 1–5 (multi-stage failure; retried job with `previousAttempts`; canceled
   build; `succeededWithIssues` only; failure without a log), plus definitions, builds pages, and a
   logs list. Record types follow the YAML shapes described in Microsoft documentation (Stage,
   Phase, Job, Task) and are marked [V-11].
10. **Tests.** S4-1, S4-2; Pester `Builds.Pester.ps1` for binding (`Get-AdoBuild … |
    Get-AdoBuildFailure`), the ambiguous definition name error, and `-IncludeWarnings`.
11. `verify` → exit 0.

### Session 4.2 — Logs

1. **Baseline.** `context`, `verify`.
2. **Registry.** BuildLog: GET with `Accept: text/plain`, Download timeout class, safe to retry.
3. **Byte-stream atomic write.** Add a stream overload to the atomic writer so log bytes are copied
   as received (no re-encoding) into the temp file in the destination directory, flushed to disk,
   and moved. A zero-length log is valid when the log list reports zero lines.
4. **`BuildLogService`.** `ResponseHeadersRead`; the read loop enforces 60 s inactivity and 10 min
   total (§6.6); a retry after a partial body deletes the temp file and restarts with a fresh one
   (§6.5). `-Tail N` uses the log list's `lineCount` to request only `startLine`/`endLine` for the
   last N lines (indexing [V-14]); unknown line count → full log with a warning.
5. **`Save-AdoBuildLog`.** `-BuildId`, `-LogId`, `-Tail`, `-Path <dir>` (FileSystem provider,
   existing directory; default Downloads known folder), `-Connection`, `-Project`. Pipeline
   `AdoBuildFailure` by property names `BuildId` and `LogId`. A failure without a log gets a
   per-input non-terminating error (`BuildLogNotAvailable`) and processing continues.
   `SupportsShouldProcess`: `-WhatIf` lists files and downloads nothing. File name
   `Build-<id>-Log-<logId>.txt`; overwrite by default (§13.3); output `FileInfo`.
6. **Tests.** S4-3; Pester `BuildLogs.Pester.ps1` (`-WhatIf`, `FileInfo`, failure without a log,
   the §15.5 example pipeline against `FakeAdoServer`).
7. **Live script.** Create `tests/Live/Triage.Live.ps1` (section 8).
8. Run the offline done check (section 7).

## 8. Live checks at work (later)

With the signed, installed module. `Triage.Live.ps1` reads `ADOTOOLKIT_LIVE_PROFILE`,
`ADOTOOLKIT_LIVE_DEFINITION` (name or ID), `ADOTOOLKIT_LIVE_BUILD_ID` (a failed run), and optionally
`ADOTOOLKIT_LIVE_RETRIED_BUILD_ID` (a run with a retried job or stage). It holds log ranges in memory
only, prints `PASS|FAIL|INCONCLUSIVE <ID> <structural note>`, and writes nothing.

| V-11 | Record `type` values seen (for example Stage, Phase, Job, Task) match the fixtures; a retried run exposes `previousAttempts`, `attempt`, and `identifier` as fixtures assume (inconclusive without a retried run) |
| V-14 | BuildDefinitionsList and BuildsList page through `x-ms-continuationtoken`; BuildLogsList returns JSON with `lineCount`; a `startLine`/`endLine` request returns exactly the requested number of lines (count compared in memory, content not printed) |

## 10. Risks

| Risk | Mitigation |
| --- | --- |
| YAML record types and attempt fields differ on Server 2020 (V-11) | Derivation keyed on `parentId`, `identifier`, `attempt`, and `result`, not on type names; fixtures marked [V-11] |
| "Deepest failed record" is ambiguous with canceled builds or failed parents without failed children | Explicit fixtures 1 and 3; parents qualify only when no descendant qualifies |
| Definition names repeat across folders | Exact-name resolution with an ambiguity error; `-Definition <id>` always works |
| Build list paging uses a different continuation mechanism (V-14) | Paging strategy is registry data; corrected by the live check |
| Log line range indexing (0- or 1-based, inclusive) (V-14) | Range computed in one function with tests; corrected by the live check |
| Large logs trip the inactivity timeout or total budget | Download class; streaming copy; clear `AdoTimeoutException` |
| Logs re-encoded or truncated | Byte copy with no decoding; retry restarts the file |
| Scope creep into test results | DD-016 boundary stated at the top of this plan |
