## 1. Working rules (every session)

- Start with `pwsh -NoProfile -File .\tools\dev.ps1 context`. Read `AGENTS.md` plus the nested
  `src/AGENTS.md` and `tests/AGENTS.md`. Use `dev.ps1 find` and `rg` for focused reads; read only
  the spec sections listed for your session.
- The spec is normative; this plan gives order and scope. If they disagree, follow the spec,
  stop, and tell the user. Never change an acceptance ID.
- The gate is `pwsh -NoProfile -File .\tools\dev.ps1 verify` (exit 0 pass, 1 fail, 2 incomplete).
  Done means exit 0, `"Status":"pass"`, no warnings. Never report a result you did not observe.
- **Ask the user first** before `dotnet restore`, any package change, any install, or any other
  network access. This plan needs no new package.
- No ADO access, no network in tests (fake `HttpMessageHandler`, loopback `FakeAdoServer`). Fixture
  hosts use `.test`. Tests never open files or browsers.
- Git lifecycle belongs to the developer: inspection commands only; never create a repository,
  commit, or push.
- If the agent sandbox blocks a step this plan requires (network after the user authorizes it,
  the NuGet or PowerShell module cache outside the workspace, loopback sockets or temporary files
  during `verify`), request elevated permission for that command. Never weaken tests or the gate
  to fit the sandbox.
- Data boundary (DD-010, DD-020, DD-022): synthetic fixtures only. Real attachments, traces, and
  reports are work data and never enter the repository.
- Names (DD-024): the Core folder is `TestRuns/` and the fixture folder is
  `tests/Fixtures/TestRuns/` (never `TestResults/`, which the template excludes and Git ignores).
  No `bin`, `obj`, `artifacts`, `build`, `dist`, `coverage`, `target`, `secret(s)` directories; no
  file name matching `*.log`, `*credentials*`, `*.local.*`, `*.key`, `*.pem`, `*.pfx`, `*.p12`,
  `.env*`. Malformed JSON fixtures end in `.json.txt`. The 2 MiB message, over-limit attachments,
  and depth-65 JSON are generated by tests.
- Tag acceptance tests: xUnit `[Trait("Acceptance", "<ID>")]`, Pester `-Tag '<ID>'`.
- All labels and messages come from `.resx` in English and French; script assets contain no words.
- `tools/check.ps1` must stay inside the template's 300-second stage timeout. This slice adds the
  most tests, so measure `project-check` every session and keep generated inputs small.
- End each session at a green `verify`, update `docs/plans/README.md`, and hand off: verify
  status and exit code, acceptance IDs covered, spec rows updated, authorizations used,
  deviations, open items, and new French strings for review.

**Plan decisions** (within the spec's latitude; state them in handoffs):

- **Detail limit ordering.** `maximumReportedFailures` is applied in report order, but a rerun
  group's classification is only known after pass 2. When the limit applies, order candidates
  with pass-1 data: a failure-class parent outcome counts provisionally as Failed, otherwise as
  Flaky; then storage, automated name, and result ID. Record the observed rerun parent outcomes in
  V-22 notes.
- **Bars and cells agree (§15.12).** For the current build, the summary counts and cells use the
  final classification (after pass 2) for detailed identities and the pass-1 classification for
  the rest. History builds use pass-1 classification throughout. Tests assert that each bar's
  counts equal the tally of its cells for reported identities plus counted-only identities.
- **Golden files and the script.** Golden comparison replaces the `<script>` body and its CSP
  hash with fixed placeholders, so script edits do not churn every golden file. S5-5 tests verify
  the real bytes and hashes.
- **Structural assertions** use toolkit markers (`data-*` attributes, ordinal anchors) and encoded
  expected strings. No HTML parser package is added.

## 5. Work steps

### Session 5.1 — Retrieval, attempts, classification, history

1. **Baseline.** `context`, `verify`; record the `project-check` duration.
2. **Registry.** Add the seven endpoints with the versions, paging, `Accept` headers, and timeout
   classes in §6.2. Mark every fixture [V-19]–[V-25].
3. **Build and runs (§15.9 steps 1–2).** BuildGet unless an `AdoBuild` is piped; validate
   `CollectionUri`. Use the build `uri`, composing `vstfs:///Build/Build/<id>` when absent.
   TestRunsList with `buildUri` and `includeRunDetails=true`, TopSkip with the §6.4 guards. No runs
   → `NoTestRuns` (Info). A build or run not completed → `TestRunInProgress` (Warning).
   `Get-AdoTestRun -BuildId`, pipeline `AdoBuild` by value, emits `AdoTestRun`.
4. **Pass 1 (§15.9 step 3).** TestResultsList per run with `detailsToInclude=None`, `$top` at most
   the documented maximum, all pages, lightweight fields only. Never use the server `outcomes`
   filter.
5. **Identity and attempts (§15.10).**
   - Identity: `automatedTestStorage` (ordinal, ignore case) plus `automatedTestName` (ordinal).
     No automated name → its own identity keyed by run and result ID, one attempt, no history
     cells, `UngroupedTestResult`.
   - Attempt sources and ordering exactly as the table: rerun sub-results (`sequenceId`, then
     `startedDate`, then sub-result ID), run re-attempts (run pipeline attempt, else run
     `startedDate`, then run ID), single result. Combined: run first, then sub-result.
   - `DataDriven`, `OrderedTest`, and `Generic` groups are never attempts.
   - A `Rerun` parent is always a detail candidate.
   - Outcome classes per the Q-23 default; unknown strings kept verbatim.
   - Classification table; report order: Failed before Flaky, then storage, name, result ID.
6. **Pass 2 (§15.9 step 4).** TestResultGet with `detailsToInclude=Iterations,WorkItems,SubResults`
   for every result record holding an attempt of a candidate identity, in report order. Stop after
   `maximumReportedFailures` identities → `FailureLimitExceeded` (Error), `Status = Partial`; the
   rest are counted only. Map every §15.11 attempt field. Unknown scalar top-level fields go to
   `AdditionalFields`; custom fields to `CustomFields`; sub-results nest at most 3 levels.
   `testCase.id` arrives as a string: non-integer → `InvalidTestCaseReference`.
7. **Attachment metadata (§15.9 step 5).** TestResultAttachmentsList per detailed result;
   TestSubResultAttachmentsList per attempt or iteration sub-result. Set `Kind` from the extension
   (§15.13); `DownloadStatus = NotRequested`.
8. **Test Case links (§15.9 step 6).** Distinct valid IDs → one WorkItemsBatch pass with §9.1
   reconciliation; `AdoTestCaseLink` with title, state, rev, `WebUrl`, `IsResolved`. Missing →
   `UnresolvedTestCase`, link kept.
9. **History (§15.12).** Window query: `definitions`, `statusFilter=completed`,
   `queryOrder=finishTimeDescending`, `maxTime` = current finish or queue time, and `branchName`
   = current `sourceBranch` for `SameBranch`. The current build is always included and last. For
   each earlier build: TestRunsList and pass 1, same grouping and classification. Produce summary
   counts (Flaky a subset of Passed) and per-test cells (Passed, Failed, Flaky, Other, NotRun,
   Unavailable). `maximumHistoryRequests` → `HistoryLimitExceeded`, older builds Unavailable. A
   per-build failure other than authentication, authorization, or cancellation →
   `HistoryUnavailable` for that build. Listings are cached for the invocation, so piped builds of
   one definition share them. History never changes `Status`.
10. **`Get-AdoBuildTestFailure`.** `-BuildId` or pipeline `AdoBuild`; `-HistoryCount` 1–50 (config
    default 10); `-HistoryScope SameBranch|AllBranches` (config default). One
    `AdoBuildTestFailureSet` per build. `Write-Progress` per stage with counts; cancellation
    observed everywhere. Format views and help.
11. **Fixtures.** Test results 1–13 in `tests/Fixtures/TestRuns/`, cataloged with V-items.
12. **Tests.** S5-1, S5-2, the history model part of S5-3, and the resolution part of S5-8; Pester
    `TestRuns.Pester.ps1` for binding and one set per piped build.
13. **Live script.** Create `tests/Live/TestFailures.Live.ps1` with V-19–V-25 (section 8).
    **Recommended:** run it at work (checkpoint W5 in the roadmap) before session 5.2, because
    every fixture shape in this session is unconfirmed.
14. `verify` → exit 0.

### Session 5.2 — Visual baseline, lexers, charts

1. **Baseline.** `context`, `verify`.
2. **`report-base.css` (§12.7).** Tokens on `:root` (dark default and the only screen theme,
   Q-30), layout, components, accessibility rules, and the print palette. Embedded resource; no
   interpolated values. CSS `content` holds glyphs only.
3. **Contrast test.** Parse the custom properties from the embedded CSS. Assert body text and code
   tokens ≥ 4.5:1 against their backgrounds, and chart marks, meaningful borders, and focus ring
   ≥ 3:1, for screen and print palettes. The test reads the CSS; no duplicate token table.
4. **Status presentation.** Glyph + localized label for every status (`✕ Failed`, `✓ Passed`,
   `≈ Flaky`, `– Other`, `? Unavailable`); never color alone.
5. **Lexers (DD-021).** Pure functions returning (kind, text) tokens, with the invariant that the
   concatenated token text equals the input exactly.
   - Stack trace (.NET): English and French frames (`at … in …:line n`, `à … dans …:ligne n`,
     [V-29]), inner-exception and rethrow separators in both languages, exception header lines,
     async frames, generic types, frames without paths, URLs. Framework-frame class for the listed
     prefixes and a first-user-frame marker.
   - Error message: leading exception type, quoted strings, numbers, assertion markers in English
     and French, MSTest `<…>` delimiters, URLs.
   - JSON: `JsonDocument` (max depth 64, no comments, no trailing commas) pretty-printed with two
     spaces, then tokens.
   - Unrecognized lines become plain tokens; lexing never throws for content.
   - Display limit 1 MiB of characters, cut at a line boundary where one exists →
     `TestTextTruncated`.
6. **`UrlDetector`.** Terminators, excluded trailing punctuation, unbalanced `)`/`]`,
   `Uri.TryCreate` with `http`/`https` and no user info; every other scheme stays text.
7. **`HighlightedCodeWriter` (§11.4).** `<pre><code class="lang-…">` with a language label; each
   token encoded separately and wrapped in a `<span>` whose class comes from a fixed set; URLs
   become `<a rel="noreferrer">` with an attribute-encoded `href` and encoded original text. Reuse
   the report encoding helper that keeps U+00A0/U+202F literal.
8. **Charts.** `RunHistoryChart` inline SVG: stacked passed/failed/other segments, count labels
   when space allows, current build outlined with a "This run" label and `aria-current="true"`,
   hatched unavailable bars, each bar linking to the build's test results view with a `<title>`
   (build number, branch, finish time, four counts), invariant numerics, and the `<details>` data
   table. `HistoryStrip` and `AttemptStrip` with glyphs and labels.
9. **Fixtures.** Test results 14–15 (2 MiB message generated), text parts of 16 (hostile), and
   Attachments 2 (valid JSON; malformed as `.json.txt`; above-limit and depth-65 generated).
10. **Tests.** Lexer expectations and round-trip over every fixture (S5-4 part), URL detection,
    chart markup (S5-3 rendering part), contrast.
11. `verify` → exit 0.

### Session 5.3 — HTML report, script, CSP, golden files

1. **Baseline.** `context`, `verify`.
2. **Report model.** `TestFailureReportModel` from an `AdoBuildTestFailureSet`, report culture
   (§3.6 order), labels, diagnostics re-rendered in report culture (§7.4), and toolkit-built links
   (§15.14): build and its test results view with run and result selection, definition, run,
   result, commit (only for Git, a GUID repository ID, and a 40-hex source version, each escaped),
   Test Case and bug work items. Routes are marked [V-26].
3. **HTML renderer (§15.14).** Head per §12.2 (`<meta charset>` first, `lang`, generator marker),
   with the CSP meta element before any style or script. Page order: sticky top bar and secondary
   line; history chart and data table; failure index; failure cards; diagnostics.
   - Cards: header, Test Case link rules, history strip with legend, and one `<details>` per
     attempt (failure-class open, others closed) with every present field.
   - Error, stack, and JSON blocks come from session 5.2.
   - Attachments list ADO name, size, and a link to the result in ADO. Local links and previews
     arrive in 5.4.
   - Anchors `f-<ordinal>`, `f-<ordinal>-a<n>`, `f-<ordinal>-a<n>-att<id>`; no `id` from remote
     text.
   - Markers `data-failure-count`, `data-attempt-count`, `data-history-count`.
4. **Script asset `test-failures.js` (§15.15).** Static, identical for every report, no words
   (labels from `data-label-*` and `<template>`). It implements the behavior table (filter,
   toggles, `/`, `j`/`k`, `o`, expand and collapse all, fragment opening, framework-frame toggle,
   wrap toggle, copy with select fallback, `<dialog>` image viewer, `beforeprint`). Controls that
   need script carry `hidden` and are revealed by the script. Handlers attach from the script;
   `textContent` only. Keep it small: behavior is checked by the S5-9 browser spike, not by an
   offline runner.
5. **CSP (§15.15).** `ContentSecurityPolicy` hashes the exact UTF-8 bytes written inside each
   `<script>` element (SHA-256, base64), one source per element, and emits exactly
   `default-src 'none'; script-src 'sha256-…'…; style-src 'unsafe-inline'; img-src 'self' data:;
   base-uri 'none'; form-action 'none'` on one line.
6. **Validation (§15.16, except attachment files).** Generator marker; the three counts; CSP hashes
   match script contents one to one; no `<script` element has `src`.
7. **Golden files.** Failed, flaky, partial, and hostile fixtures in `en-US` and `fr-CA`: 8 files
   `tests/Fixtures/Reports/testfailures-<case>.<culture>.html`, with pinned clock and version and
   the script placeholder rule. Open one English and one French output in a browser before
   approving.
8. **Tests.** S5-4 golden files, S5-5, S5-8 rendering; forbidden-token scan of the script asset;
   no fixture string inside any `<script>`; structural completeness with scripts ignored.
9. `verify` → exit 0.

### Session 5.4 — Attachments, commit order, export, browser spike

1. **Baseline.** `context`, `verify`.
2. **`AttachmentDownloader` (§15.13).**
   - Download in report order.
   - Known size above `maximumAttachmentBytes` → `TooLarge` + `AttachmentTooLarge`. While
     streaming, enforce the byte count and delete the partial file.
   - The running total stops at `maximumTotalAttachmentBytes`: `AttachmentBudgetExceeded` once,
     remaining attachments `BudgetExceeded`.
   - Failure after retries → `AttachmentDownloadFailed` (the report still commits);
     authentication, authorization, and cancellation stay terminating. A retry restarts the file.
   - Toolkit names only: `r<runId>-<resultId>[-s<subResultId>]-a<attachmentId>.<ext>`.
   - Content checks: PNG signature; JSON parse (depth 64) with inline preview up to
     `maximumInlineJsonBytes`; HTML linked and labeled as test output; everything else `.bin`.
     A failed check → `.bin`, never previewed, `AttachmentContentMismatch`.
   - Set `LocalRelativePath` and `DownloadStatus`.
3. **`GenerationFolderCommit` (§13.4).** Steps 1–8 exactly, with an injectable failure at every
   step:
   - Stamp `yyyyMMddTHHmmssfffZ` chosen before rendering.
   - `-NoClobber` refusal before any download; non-overwriting move for the report.
   - Folder rename fails if the name exists; on a report move failure, the new folder is deleted.
   - Old generation folders deleted only when they are direct children whose names match
     `<base>.files-` plus exactly the stamp format; reparse points skipped with a warning;
     deletion failures are warnings.
   - No attachments → no folder, and step 8 still runs.
   - Tests create a junction with `cmd /c mklink /J` (no elevation) for the reparse-point case.
4. **Validation.** Add the §15.16 attachment rule: every local link names an existing, non-empty
   file of the recorded size in the temporary folder, using the final relative folder name.
5. **Renderer completion.** Thumbnails (CSS-scaled, lazy `<img>`, link to the full file), inline
   JSON blocks, local HTML links labeled as test output, `.bin` links with original name and size.
   Update the golden files where attachment markup changed.
6. **`Export-AdoBuildTestFailure` (§15.8, §15.16).**
   - Pipeline `AdoBuildTestFailureSet`; `-Culture`; `-Path` (an `.html` file only for exactly one
     set, otherwise a directory; later sets with a file path get a per-input error; default
     Downloads); default name `Build-<id>-TestFailures.html`.
   - `-SkipAttachments`: no downloads, no folder, attachments listed with ADO names and sizes.
   - `-NoClobber`, `-Open` through `IDocumentLauncher`. One `ShouldProcess` covers steps 3–8, and
     `-WhatIf` names the report and folder and downloads nothing.
   - Output `FileInfo` with an `AttachmentDirectory` note property when a folder was created.
   - Help in both cultures.
7. **Fixtures.** Attachments 1–8 in `tests/Fixtures/Attachments/` (a tiny valid PNG; PNG without

   size; budget; failing and partial downloads; sub-result attachment). Hostile remote file names

   to `.gitattributes`. `FakeAdoServer` serves binary content.
8. **Tests.** S5-6, S5-7, the export part of S5-3 (a history build returning 500 still commits),
   plus Pester `TestFailureExport.Pester.ps1`.
9. **S5-9 local browser spike (V-27).** Generate a sample report with attachments from synthetic

   1. The hash-allowed inline script runs from `file://` (the filter works).
   2. Sibling PNG thumbnails load under `img-src 'self' data:`.
   3. `<dialog>` opens and `Esc` closes; `<details>` toggles; SVG `<title>` shows on hover.
   4. A link to a local HTML attachment opens.

## 10. Risks

| Risk | Mitigation |
| --- | --- |
| Every Test-area route, version, and field is unconfirmed (V-19–V-25), so fixtures may be wrong | Retrieval first; registry and DTOs isolated; run the live script at work (W5) before sessions 5.2–5.4 |
| Rerun representation (V-22) changes identity and classification logic | Grouping isolated in `AttemptGrouper`; all three sources covered by fixtures; plan decision on limit ordering recorded |
| `img-src 'self'` does not load sibling PNGs from `file://` (V-27) | S5-9 spike at home before acceptance; spec change only with user approval |
| Script behavior cannot be tested offline | Small script, token scan, script-free completeness tests, manual browser checklist |
| CSP hash mismatch from line endings or encoding | Hash computed from the exact bytes written; validation before commit |
| Golden churn from CSS or script edits | Script placeholder rule; pinned clock and version; one browser review per approval |
| `project-check` passes 300 s with the largest test set | Generated inputs sized minimally; measure each session; if needed, ask the user before any template timeout change |
| Folder rename or delete blocked by antivirus or open handles | Commit order leaves the previous report consistent; clear `AdoFileOutputException`; warnings for cleanup |
| Reparse-point tests need a junction | `mklink /J` needs no elevation; test fails loudly if creation fails (no silent skip, which would make verify incomplete) |
| French runtime stack traces differ from assumed forms (V-29) | Lexers degrade to plain tokens; fixtures corrected from a structural description |
| Hostile remote names reach paths or ids | Toolkit-generated names and ordinal anchors only; hostile fixture 16 and S5-6 name assertions |
| Large reports (1,000 failures with 1 MiB traces) exhaust memory | Display truncation; streaming render; failure limit |
